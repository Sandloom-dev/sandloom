# Split <app> into services

The code does not change; the topology does. `uv run sandloom docs recipe split`
has the same steps.

1. **Choose the services.** Each module runs in exactly one service; a
   service may hold several. The bundled modules (identity, tenancy,
   billing) can each be their own.
2. **Write the split,** one command per service, from the app root:

   ```bash
   uv run sandloom add deploy identity
   uv run sandloom add deploy tenancy
   uv run sandloom add deploy billing
   uv run sandloom add deploy <module> <other_module> --service <svc>
   ```

   - The first run creates `deploy/compose/microservices.yml`,
     `deploy/gateway/nginx.conf` and the database init script. Never
     hand-write them.
   - Every run re-derives each service (its database, a migrate one-shot,
     RPC keys, a worker for `tasks.py`, one beat for periodic tasks),
     `SERVICE_BINDINGS`, `RPC_ALLOWED_CALLS` and the gateway routes.
   - The same command again changes nothing. A new module:
     `uv run sandloom add deploy <m> --service <svc>`; after a code change (a
     new consumed contract, a route prefix): `uv run sandloom add deploy
     --refresh`.
3. **Hand edits** go outside the `# >>> generated by sandloom add deploy` blocks
   (or in a compose override file). An edit inside one makes the next run
   refuse with a diff (`--force` overwrites it).
4. **Keys.** Development only: `uv run sandloom keys dev-env --out
   deploy/.env.microservices`, then `docker compose --env-file
   deploy/.env.microservices -f deploy/compose/microservices.yml up
   --build`. Production: `uv run sandloom keys generate` (the JWT pair; `--purpose
   rpc --service <caller>`, `--purpose rpc-dh --service <provider>`) into a
   secret store; each `${VAR:?...}` in the profile names its command.
5. **Check:**

   ```bash
   uv run sandloom add deploy --check   # invariants (SANDLOOM-T014), every service boots alone
   uv run sandloom test                 # schema & deploy checks the profile too
   ```

An optional contract whose provider is not deployed must degrade
explicitly (404, 501 or 503), never with a 500.

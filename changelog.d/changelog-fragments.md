### Changed

- **Changelog entries are per-branch fragments, `changelog.d/<alias>.md`, folded into `CHANGELOG.md` at release** (changelog-fragments). A branch used to add bullets under `## [Unreleased]`; GitHub ignores the union merge driver of `.gitattributes`, so every merged PR turned the others CONFLICTING and cost a local merge and a full CI rerun. A branch now adds one file of its own, with its bullets under `### Breaking changes`, `### Security`, `### Deprecated`, `### Added`, `### Changed` or `### Fixed`, and leaves `CHANGELOG.md` alone. `python3 tools/packaging/changelog_fragments.py --check` validates them (pre-commit hook `changelog-fragments`, and `tests/architecture/test_changelog_fragments.py` in CI); `--fold <version>` is the release step: it writes `## [<version>] — <date>` from the loose bullets still under `## [Unreleased]` plus every fragment grouped by kind, empties `## [Unreleased]` and deletes the fragments. `pypi_release.py` refuses to prepare a coordinated release while fragments are left, so fold in the release preparation PR. The bullets already under `## [Unreleased]` stay where they are. Unreleased fragments are not rendered on the docs site (it includes `CHANGELOG.md` only); they appear with the release. No upgrade steps.

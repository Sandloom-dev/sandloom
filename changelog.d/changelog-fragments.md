### Changed

- **Changelog entries are per-branch fragments, `changelog.d/<alias>.md`, folded into `CHANGELOG.md` at release** (changelog-fragments). A branch used to add bullets under `## [Unreleased]`; GitHub ignores the union merge driver of `.gitattributes`, so every merged PR turned the others CONFLICTING and cost a local merge and a full CI rerun. A branch now adds one file of its own, with its bullets under `### Breaking changes`, `### Security`, `### Deprecated`, `### Added`, `### Changed` or `### Fixed`, and leaves `CHANGELOG.md` alone. A change to one package's own `packages/<package>/CHANGELOG.md` goes into `changelog.d/<package>/<alias>.md`. `python3 tools/packaging/changelog_fragments.py --check` validates them (pre-commit hook `changelog-fragments`, and `tests/architecture/test_changelog_fragments.py` in CI). `--fold <version>` is the release step, run in the release preparation PR after `sync_release.py --version`: it writes `## [<version>] — <date>` from the fragments grouped by kind, empties `## [Unreleased]` and deletes the fragments; `--package <package>` does the same for a package's changelog, and a version that differs from the package's `pyproject.toml` is refused. The loose bullets still under `## [Unreleased]` are folded once, under `### Changed`. `pypi_release.py plan` (and `select`) refuse a release whose scope still has fragments, a dry run included, so a release that skipped the fold fails before any package builds. Unreleased fragments are not rendered on the docs site (it includes `CHANGELOG.md` only); they appear with the release. No upgrade steps.

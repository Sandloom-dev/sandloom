### Fixed

- **A model refused when it is declared no longer fails the loading of every module that follows** (fix-main-sp-s2-ci). A class whose declaration failed (a `Versioned` model whose own `__mapper_args__` dropped the stale-write check, a table without a primary key) stays registered in `Base.registry`, half built, until the garbage collector frees it, and `Base.registry.mappers` raises `UnmappedClassError` for as long as it does. The manifest, the database-feature preflight, `sandloom migrate new`, `sandloom extract`, the migration chain checks and the tenant key check all read that collection, so a module loaded after the refusal failed with `Class '...' is not mapped`. They read the models through `sandloom.core.sql_alchemy.base.base_mappers()` now, which leaves a class that never got a mapper out. No setting or API of `sandloom.sdk` changes.

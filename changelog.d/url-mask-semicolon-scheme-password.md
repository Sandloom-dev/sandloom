### Security

- **A password or a query value that holds `;` followed by `x://` is masked whole** (url-mask-semicolon-scheme-password). The masker of the migration logs, `sandloom backup plan`, `sandloom config` and `sandloom doctor` (`sandloom.core.migrations.url_mask`) read every `;` that starts a `scheme://` as the separator of a kombu broker list, so `postgresql://u:pw1;kw://pw2@h/db` (a valid url, password `pw1;kw://pw2`) printed `postgresql://u:pw1;kw://***@h/db`, and `?password=ab;cd://x` printed `cd://x`. A `;` now does not separate when the piece before it is a password that is still open (`user:` followed by something that is not a port, no `@`) or ends inside the value of a secret-named query parameter (`password`, `token`, `key`, `sig`, ...); the log scrubber (`sandloom.core.observability.guardrails`) follows the same rules. Lists of urls that each hold an `@`, a port (`h1:6379;redis://h2`) or an IPv6 host still split and print as before. Two changes of reading follow: the value of a secret-named query parameter now runs through a `;` that starts a url (`redis://h1/0?password=a;redis://h2/0` prints `redis://h1/0?password=***`, the second url is part of the value), and a password of digits only before the `;` (`u:123;b://c@h`) still reads as a host and a port. No upgrade step.
- **The url masker scans a long word in linear time** (url-mask-semicolon-scheme-password). A scheme is now at most 32 characters; the unbounded form rescanned the rest of a long word from every position, so `mask_url_credentials` took seconds on a 32 000 character token after a `://`.

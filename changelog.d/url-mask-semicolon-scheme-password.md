### Security

- **A password or a query value that holds `;` followed by `x://` is masked whole** (url-mask-semicolon-scheme-password). The masker of the migration logs, `sandloom backup plan`, `sandloom config` and `sandloom doctor` (`sandloom.core.url_mask`, which `sandloom.core.migrations.url_mask` re-exports) read every `;` that starts a `scheme://` as the separator of a kombu broker list, so `postgresql://u:pw1;kw://pw2@h/db` (a valid url, password `pw1;kw://pw2`) printed `postgresql://u:pw1;kw://***@h/db`, and `?password=ab;cd://x` printed `cd://x`. A `;` now does not separate when the piece before it is a password that is still open (`user:` followed by something that is not a port, no `@`) or ends inside the value of a secret-named query parameter (`password`, `token`, `key`, `sig`, ...); the log scrubber (`sandloom.core.observability.guardrails`) runs the same masker. Lists of urls that each hold an `@`, a port (`h1:6379;redis://h2`) or an IPv6 host still split and print as before. Two changes of reading follow: the value of a secret-named query parameter now runs through a `;` that starts a url (`redis://h1/0?password=a;redis://h2/0` prints `redis://h1/0?password=***`, the second url is part of the value), and a password of digits only before the `;` (`u:123;b://c@h`) still reads as a host and a port. No upgrade step.
- **A comma after a port keeps the hosts of a multi-host url in a list** (url-mask-semicolon-scheme-password). `redis://h1:6379,h2:6379;redis://u:pw@h3` printed `redis://***@h3`, so the hosts `h1` and `h2` vanished from the logs and the backup plan; the `,` now ends a port like a `/` does, and the list splits and prints with its hosts (`redis://h1:6379,h2:6379;redis://***@h3`). A password of digits followed by a `,` before a `;` reads as a host list likewise.
- **The url masker no longer slows down on a long chain of `;x://` pieces** (url-mask-semicolon-scheme-password). A line of repeated `y://u:p;` without an `@` took 12 s in `mask_url_credentials` (22 s in the log scrubber) on 50 000 characters, because the open-password branch chained every `;x://` piece to the end of the line from every start: the chain is capped at 8 pieces (`sandloom.core.url_mask.MAX_CHAINED_SCHEMES`) and those lines take well under 0.1 s. `split_url_list` searched its growing open piece again at every `;`, so 50 000 characters of `;sig=a;x://` took 4 s in the migration logs; it now joins at most 8 separators into one piece and keeps the rest of the url as one part, masked whole (hosts of later urls of that list go with it, no secret stays), and it searches only the text after the last `@` of a piece. A password that chains more than eight `;x://` pieces has the pieces before its last eight printed by `mask_url_credentials` and the log scrubber (`_mask_url` masks it whole). No upgrade step.
- **The url masker scans a long word in linear time** (url-mask-semicolon-scheme-password). A scheme is now at most 32 characters; the unbounded form rescanned the rest of a long word from every position, so `mask_url_credentials` took seconds on a 32 000 character token after a `://`.

### Changed

- **The periodic-task recipe and scaffold teach `at_least_once`** (dx-eval-t6-t8). The `periodic-task` recipe and the `sandloom add task --periodic` docstring no longer say a periodic run repeats by default: a task is acknowledged when it starts (at most once), so a worker that dies mid-run loses that slot. Work that must not be lost takes `@periodic(..., at_least_once=True)` with the taskqueue feature `redelivery` declared next to `periodic` (SANDLOOM-C033). The recipe's purge opts in and shows the declaration; `docs/modules/background/tasks.md` says the same. The scaffold still writes no `at_least_once`.
- **DX eval check `t6_team_overview` accepts a live billing read** (dx-eval-t6-t8). The billing side of the overview may be a projection over `billing.subscription` events or a live read of `billing.entitlements.v1` at request time, as the `projection-from-platform-events` recipe teaches (the subscription events carry no version). The `tenancy.member` requirement stays.

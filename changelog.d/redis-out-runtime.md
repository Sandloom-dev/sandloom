### Added

- **`InfraProvider.backup_hint` and `InfraProvider.aclose_shared`** (redis-out-runtime). A driver package now says what its server needs to be backed up and restored (`backup_hint`, returning a `BackupHint` of `url`, `kind`, `criticality`, `backup`, `restore` and `tolerable_loss`, exported from `sandloom.driverkit`) and releases the connection pools it shares between instances at shutdown (`aclose_shared`). Both have a neutral default, so a driver that implements neither behaves as before. `InfraRegistry.aclose_shared()` calls every loaded provider's hook on shutdown, logs a failure as a warning and never raises.
- **The relay logs an error it does not recognise.** When a publish fails with an error that no driver mapped to `Unavailable` or `Timeout`, the attempt still counts as a delivery attempt, and the relay logs a warning that names the class, at most once every five minutes per class. The driver guide says what to map.

### Changed

- **The kernel runtime names no Redis** (redis-out-runtime). `sandloom backup plan`, the production profile, the task relay, the unreachable-service message and the shutdown of the default cache no longer test for `redis`, `kombu` or a `redis://` url: the Redis and Celery packages carry that knowledge. Wording changes: the plan and the unreachable message name the capability ("the cache backend", "the event bus", "the task queue") where they named "Redis", the role lines of the plan read `<capability>:<instance>`, and the refusals of the production profile say "the same server" for "the same Redis server". Upgrade steps: none for an app on the standard stack.
- **`noeviction` is advised for any Redis `atomic_store`, not only `security`.** An `atomic_store.idempotency` instance on its own Redis server now gets the `maxmemory-policy noeviction` step in the plan (it had the AOF step only).
- **A separate `atomic_store.idempotency` server is at least `required` in the plan** (it was `optional`): the kernel keeps idempotency through a restore. A server whose roles may all be lost now lists each distinct tolerable-loss note, not only the first.
- **`sandloom backup plan --json` renames the warning item** `redis endpoints` to `backing servers`. A driver that is not installed, an instance not filled, and a `security` or `idempotency` store whose driver gives no `backup_hint` are one critical warning there, instead of a listing of the url.
- **The same-server check of the production profile reads the ports as the server's identity.** Two urls of one host that both state a port are the same server when the ports are equal, whatever the scheme (`redis` and `rediss`). A url without a port is a wildcard: it is the same server when its scheme, or its `s` variant, matches. The refusal that follows is the one already documented. The check reads each url through the driver's own url option.
- **The relay classifies an outage by the error the driver mapped, not by client class names or reply words.** A driver maps its transient errors to `Unavailable`; a poison error stays a poison error. An unmapped raw Redis or kombu error is no longer recognised as an outage by the kernel.
- **The unreachable-service message now recognises `BrokerUnavailableError`.** The class was listed under a module that does not hold it, so it never matched; the line now reads "cannot reach the event bus ...".

### Fixed

- **Branches that each add a module no longer conflict in `.sandloom/inspection.json`** (inspection-merge-conflict). `sandloom generate` wrote the tracked index as one line of JSON, so any two branches that regenerated it conflicted by construction. It is now one record per line, in one order, and the file reads the same in any line order. `sandloom new` writes a `.gitattributes` with `.sandloom/inspection.json merge=union text eol=lf`, which keeps both sides where two branches add a record in the same place and the lines LF in a Windows checkout. A CRLF copy of the file still reads. `sandloom generate --check` passes on a merged file.
  Upgrade: run `sandloom generate` once (the first rewrite is a large diff; an index in the old one-line form is also read as a `graph diff` baseline) and add `.sandloom/inspection.json merge=union text eol=lf` to your `.gitattributes`. Git applies it on a local merge; GitHub's merge button ignores merge drivers, so merge the base branch locally into a pull request that GitHub reports as conflicting. A branch still on the old one-line file and a branch on the new format conflict in this file once: merge, then run `sandloom generate`.

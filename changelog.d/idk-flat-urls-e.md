### Changed

- **`sandloom dev` writes one `INFRA` line, not `CACHE_URL` and `BROKER_URL`** (idk-flat-urls-e). The managed block of `.env` is now `DATABASE_URL` plus an `INFRA` JSON line that gives every Redis instance of your composition root's `DEFAULT_INFRA` its own url on the checkout's Redis: `cache` and `broadcast` on the cache database, every instance that holds state (`atomic_store`, `lease`, `eventbus`, the Celery broker) on the broker database, never the cache's. An `INFRA` of your own in `.env` is merged into the block's: per instance and per option your value wins, an instance only you name is kept, and the commented-out original line stays in the file. A broken `INFRA` of yours (not a JSON object) stops `sandloom dev up` and leaves `.env` untouched. **Upgrade:** run `sandloom dev up` once to rewrite the block; delete `CACHE_URL` / `BROKER_URL` from your own `.env` lines.
- **`sandloom new` projects and the `microservices` deploy profile use `INFRA`** (idk-flat-urls-e). `.env.example`, `.env.test`, the monolith compose file and the generated `deploy/compose/microservices.yml` carry one `INFRA` with an explicit url per Redis instance, the persistent instances on their own database index. In the microservices profile every service gets the shared `INFRA` plus its own `taskqueue.default.broker` (one database per service); the profile check treats that broker as the one allowed difference. **Upgrade:** a profile generated before keeps its brokers when you run `sandloom add deploy --refresh`, which re-derives each service's `INFRA`; move the shared `CACHE_URL` line of `x-common-env` into the shared `INFRA` by hand.
- **The profile check compares the url `cache.default` and `broadcast.default` resolve to** (idk-flat-urls-e). While `CACHE_URL` still fills them, a service with its own `CACHE_URL` and no `INFRA` url there split the rate-limit and idempotency state yet passed SANDLOOM-T014; the check now resolves each process's url (its `INFRA` url, else `CACHE_URL`) and refuses a difference. `sandloom add deploy --refresh` also gives a service that names no broker the next free database instead of the cache's `/0`.

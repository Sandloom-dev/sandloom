### Added

- **`sandloom.stack` entry-point group and `sandloom.driverkit.stack_service`** (redis-out-batch-a2). The backing server of the standard stack is described by the driver package: an object with the members of `StackService` (names and ports of its compose services, `parse`, `problem`, `clients`, `empty_indexes`, `flush`, and the compose text of each generated file). `sandloom-redis` registers it (`sandloom_redis.stack.STACK_SERVICE`); the kernel loads it by driver name and holds no client, image name or URL layout of its own. `sandloom dev` and `sandloom new` / `sandloom add deploy` say which package to install when none registers one.

- **A bare `uvx --from "sandloom==<version>" sandloom new` works, and the wizard asks for the stack** (redis-out-batch-a2). `--stack <name>` (today `standard`: PostgreSQL and Redis) answers it; the kernel's list holds the name, a summary and the extras to install, never compose text or URL forms. When the stack's package is importable `sandloom new` writes its files as before; when it is not, the files carry a marker, `sandloom new` runs `uv sync`, `sandloom add stack` and `sandloom generate` in the new app, and `add stack` fills the markers from the package in the app's environment. The bytes are the same on both paths (`test_scaffold_standard_stack_snapshot.py` checks both). With no `uv`, or when a step fails (no network), `sandloom new` prints the commands to run later, never a traceback; `--services external` needs the package at once. New command: `sandloom add stack`.
- **`sandloom dev prune` and `sandloom dev up --services external` guard the keyed server's indexes** (redis-out-batch-a2). `prune` stops before any pass when the state names no keyed server; `up` checks every checkout's pair of database indexes again when it names another keyed server (also when the state was in Docker mode in between, which hands indexes out unchecked), gives a pair that holds keys a free one, saves the state first and then rewrites the `.env` block and `.env.test.local` of every other checkout; a checkout that cannot be written is named and the next `dev up` writes it again, even on the same server.
- **`sandloom check`, `generate`, `test` and `dev up` stop with one line while the stack's files still carry a marker** (redis-out-batch-a2): run `uv run sandloom add stack`. A stack other than the default is recorded in `[tool.sandloom] stack` of the app's `pyproject.toml` and `sandloom add stack` fills the markers from that stack's package; the default one is not recorded, so a standard app's files stay as they were. An app cannot be named `redis`, `hiredis`, `celery` or `kombu` even where those packages are not installed, and the repeat command of `--services external` installs `sandloom[redis,celery]`.
- **`sandloom_redis.stack`** brackets an IPv6 literal in every URL and address it builds; the refusal of a Redis URL no longer prints a password written in the query string. The test harness's `same_database` reads `/00` and `/0` as the same database index.

### Changed

- **`sandloom dev` and the deploy scaffold take the Redis server from `sandloom-redis`** (redis-out-batch-a2). The kernel keeps a generic dev-service engine and PostgreSQL. The Redis pings, `CLIENT LIST`, `FLUSHDB`, the scheme refusals (`rediss://`, an ACL user, URL options) and the compose text (`redis:7-alpine`, the persistence flags, the CI service and the microservices blocks) move to `sandloom_redis.stack`. The wheel of `sandloom` imports no Redis client, guarded or not (`check_package_distributions` no longer exempts `sandloom.core.cli.dev.services`). Every file `sandloom new` writes is byte for byte what it was: `tests/integration/with_batteries/test_scaffold_standard_stack_snapshot.py` pins it. Upgrade steps: the renames below.
- **Neutral wording in the kernel** (redis-out-batch-a2). Docstrings, help texts and messages that said Redis for a stack-wide server say "keyed server", "the durable event bus" or "a backing service" (the CLI still prints the server's own name where it talks to a person: `Redis answers at ...`).

- **The `redis` and `celery` extras of `sandloom` name the driver packages alone** (redis-out-batch-a2): `sandloom-redis[hiredis]` and `sandloom-celery`, which require the client libraries with their bounds (one place each). The installed set is the same.

### Breaking changes

- **`sandloom add deploy` needs `sandloom-redis` in its environment** (redis-out-batch-a2). An app made by `sandloom new` has it (`uv sync`); elsewhere the command stops with one line naming `sandloom[redis]` and writes nothing.

- **`--redis-url` of `sandloom dev up` and `sandloom new` is `--kv-url`; `external.redis_url` of `dev.json` is `external.kv_url`; `redis_indexes` of `sandloom dev status --json` is `kv_indexes`** (redis-out-batch-a2). Development machines only; no alias (ADR-0010). A `dev.json` that names no `kv_url` stops `dev up`, `dev status`, `dev run`, `dev reset` and `dev prune` with one line that says to run `dev up --services external --kv-url URL` again, before any database or key is touched; `dev up` no longer falls back to a server that answers on the default port. `SANDLOOM_DEV_REDIS_PORT`, `SANDLOOM_DEV_TEST_REDIS_PORT` and the compose services `redis` / `redis_test` keep their names: compose files already written read them. See "Upgrading to 0.7.0a15: dev services and the scaffold ask a package" in `docs/operate/upgrade.md`.
- **`sandloom.core.cli.dev.services.RedisServer`, `redis_ready`, `redis_clients`, `empty_indexes` and `flush_indexes` are removed** (redis-out-batch-a2): the CLI's own module, not public API. The Redis server is `sandloom_redis.stack.RedisServer` and `STACK_SERVICE`.

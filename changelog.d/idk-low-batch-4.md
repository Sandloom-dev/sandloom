### Changed

- **`InfraError` takes an optional `hint`** (idk-low-batch-4). `InfraError(message, *, capability, instance=None, hint=None)`: a new optional keyword, stored as `.hint`, a fixed sentence a driver writes for the log line of whoever reads the error chain. It never decides anything: the outbox relay still classifies an outage by the error's class and `retryable`, so an outage parks the row and never dead-letters it. This changes the recorded signature of `InfraError` and its subclasses in the public API baseline; no upgrade step, a driver that sets no hint behaves as before.
  The relay no longer knows Redis cluster replies: the `MOVED` / `ASK` label of its outage warning moved to the Redis drivers, which set the hint "cluster redirect: is the client cluster-aware?" when they map those replies (the sentence only, never the address or slot). The warning now reads `Unavailable (cluster redirect: is the client cluster-aware?)` and no longer names the reply word; a raw client error that reaches the relay unmapped is still an outage by its reply prefix, with no label.
  ADR-0016 now says `idk-ratchets-close` prunes the shrink-only allowlists to the rows that state why they stay, not that it empties them.

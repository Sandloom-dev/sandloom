### Security

- **`sandloom check` refuses a listener at the cursor in a business module (new rule `cursor-listener`, SANDLOOM-C039)** (archcheck-cursor-listener). The tenant guard reads the compiled statement inside `dialect.do_execute`. A `before_cursor_execute` listener with `retval=True` sends other SQL text or other parameters than the ones it checked. A dialect listener (`do_execute`, `do_executemany`, `do_execute_no_params`) that returns `True` makes SQLAlchemy skip the whole cursor hook. ADR-0018 decision 8 named both as a seam and added no refusal. Module code is now refused the registration statically.
  The rule catches the mistakes of ordinary code, the ones a module author or an AI agent writes in good faith. A deliberate bypass is not caught statically; row-level security, where enabled, is the boundary. It refuses a string that names a cursor event (`before_cursor_execute`, `after_cursor_execute`, `do_execute`, `do_executemany`, `do_execute_no_params`, `do_setinputsizes`) or a pool or connect event whose listener is handed the raw DBAPI connection (`connect`, `checkout`, `do_connect`, and the rest of the pool events), wherever the string stands: `event.listen`, `@event.listens_for`, an aliased `event`, `listen` or `listens_for`, `from sqlalchemy.event import listen as l`, a name bound to the constant, a `getattr` lookup. It refuses a `listen` call whose event name it cannot read, the registrar used without a call, the `event` module passed around or stored, a star import, a dynamic import of `sqlalchemy.event`, the listener list `engine.dispatch.before_cursor_execute` and a read or assignment of a dialect's `do_execute` family. A listener on any other event (`before_insert`, `load`, `after_flush`, `do_orm_execute`, `before_execute`) stays allowed. Migration files are scanned like any module file. A module's tests are not.
  The rule is wider than the two kinds ADR-0018 named: `after_cursor_execute`, `do_setinputsizes` and the pool and connect events cannot rewrite a statement, but their listeners are handed the raw cursor or connection, which is what `exec_driver_sql` and `.raw_connection()` give and what C015, C031 and C037 already refuse in a module.
  Upgrade: run `uv run sandloom check`. A module that registers a listener on a cursor-level or a pool event is reported. Move a query counter into a test of the module. The rule cannot be waived: a `# sandloom: allow` comment does not admit a listener. Nothing changes at runtime: the seam stays open to code that is not a module (a driver, the application's startup, a test), and G-TENANT-25 still names it. The rule is G-TENANT-29. `uv run sandloom explain SANDLOOM-C039` lists what it does not see.

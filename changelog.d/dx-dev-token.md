### Added

- **`sandloom dev token`: an access token for your own routes, in the first hour** (dx-dev-token). `uv run sandloom dev token [--tenant UUID] [--role NAME]... [--user UUID] [--ttl-minutes N] [--quiet]` prints a token on stdout and what it carries on stderr, so `TOKEN=$(uv run sandloom dev token)` works. The app accepts it like one it issued: it is signed with the app's own key and carries the `cpv` digests and `claims_sources` that the composition's `claim_authorities` ask for (ADR-0014), which a hand-signed JWT lacks. A `--role` or `--tenant` the composition assigns to no module is refused with the missing assignment named, never minted and then dropped by the verifier; no permissions are minted. Every token carries a sealed `dev_mint` claim, and `decode_token` refuses a token with it unless the verifier's own `ENVIRONMENT` is `dev` or `test`: a token minted with a production key (a production `.env` copied with `ENVIRONMENT=dev`) is not accepted by production. The command also refuses outside development: `ENVIRONMENT` must be exactly `dev` or `test` (unset, `Dev` and `prod` are refused; the app itself runs as `dev` when it is unset), every host of `DATABASE_URL` must be this machine (read as SQLAlchemy reads it: its address, its `host` and `hostaddr` parameters, and `PGHOST` when the url names none; loopback, `localhost`, a unix socket or a file database; no flag overrides it), and `CI` must not be set to a true value (`1`, `true`, `yes` or `on`). The check runs on the raw environment and `.env`, again on the loaded settings in the child process that composes the app, and a third time in the mint (`sandloom.core.auth.dev_token`). The signing key is never printed; a settings error is replaced by a fixed text, and the child's stderr shows only under `--debug`, without urls. The check covers `DATABASE_URL`, not the urls under `INFRA`. ADR-0014 records the amendment.

### Changed

- **The first-access-token page opens with the one-command path** (dx-dev-token). Right after "Create the application": `sandloom dev token --tenant <uuid>` and a `curl`, with no registration and no organization. The real flow follows: register, verify with the link `sandloom dev run` prints (`NOTIFIER_LOG_LINKS=true`, already in the generated `.env` of an app with identity), sign in, refresh. The Mailpit container and the hand-edited `INFRA` notification JSON are gone from the page. The page also says that a `--no-batteries` app has no module that vouches for roles or tenants, and that a tenant-scoped route there needs `TENANCY_MODE=single` and `SINGLE_TENANT_ID` in `.env` (and answers `403 tenant_not_authorized` for an `X-Tenant-Id` in multi mode). The README quickstart links the page. No upgrade step.
- **A token marked `dev_mint` is refused outside `dev` and `test`** (dx-dev-token). Only `sandloom dev token` mints one; the verification cache is now keyed on `ENVIRONMENT` as well. A token without the marker verifies as before.

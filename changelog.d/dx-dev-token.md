### Added

- **`sandloom dev token`: an access token for your own routes, in the first hour** (dx-dev-token). `uv run sandloom dev token [--tenant UUID] [--role NAME]... [--user UUID] [--ttl-minutes N] [--quiet]` prints a token on stdout and what it carries on stderr, so `TOKEN=$(uv run sandloom dev token)` works. The app accepts it like one it issued: it is signed with the app's own key and carries the `cpv` digests and `claims_sources` that the composition's `claim_authorities` ask for (ADR-0014), which a hand-signed JWT lacks. A `--role` or `--tenant` the composition assigns to no module is refused with the missing assignment named, never minted and then dropped by the verifier; no permissions are minted. The command refuses outside development: `ENVIRONMENT` must be exactly `dev` or `test` (unset, `Dev` and `prod` are refused; the app itself runs as `dev` when it is unset), `DATABASE_URL` must name this machine (loopback, `localhost`, a unix socket or a file database; a copied production `.env` that still says `ENVIRONMENT=dev` is refused, and no flag overrides it), and `CI` must not be set. The check runs on the raw environment and `.env`, again on the loaded settings in the child process that composes the app, and a third time in the mint (`sandloom.core.auth.dev_token`). The signing key is never printed; a settings error is replaced by a fixed text, and the child's stderr shows only under `--debug`, without urls. The check covers `DATABASE_URL`, not the urls under `INFRA`. ADR-0014 records the amendment.

### Changed

- **The first-access-token page is rewritten around the printed links** (dx-dev-token). Register, verify with the link `sandloom dev run` prints (`NOTIFIER_LOG_LINKS=true`, already in the generated `.env` of an app with identity), sign in; then `sandloom dev token`. The Mailpit container and the hand-edited `INFRA` notification JSON are gone from the page. The page also says that a `--no-batteries` app has no module that vouches for roles or tenants, and that a tenant-scoped route there needs `TENANCY_MODE=single` and `SINGLE_TENANT_ID` in `.env`. No upgrade step.

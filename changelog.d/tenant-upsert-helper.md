### Added

- **`tenant_upsert(Model, rows, update=[...])` upserts a tenant model's rows for the bound tenant** (tenant-upsert-helper).
  `conflict_insert` on a `TenantScoped` model is refused outside `unscoped()`, because the cursor guard cannot tell a harmless `ON CONFLICT` from one that rewrites another tenant's row. `sandloom.sdk.data.tenant_upsert` is the way in.
  It takes rows of plain Python values and the names of the columns to refresh, fills `tenant_id` from the bound tenant, conflicts on a unique key that includes the tenant column, and writes `SET column = excluded.column WHERE tenant_id = <bound>` itself.
  A row of another tenant is never the conflicting row, so it is never updated. Every other key and every foreign key acts as on a plain insert: a primary key or another unique key that another tenant holds is the database's integrity error, which shows that the key exists, and a foreign key locks the row it references, which may be another tenant's. Use keys that are not reused across tenants and composite foreign keys `(tenant_id, parent_id)`.
  A SQL expression as a value, a row that names the tenant column, a model in an inheritance hierarchy, a model whose tenant column is not named `tenant_id` in the database, a model without a unique key that includes the tenant column, a model with a column that is not exactly `sqlalchemy.Column`, a model with a `<dialect>_on_conflict*` option on a column, a constraint or an index (SQLite's `sqlite_on_conflict*` is the one that exists, and its `REPLACE` deletes the row that holds the key, whichever tenant owns it) and a call whose statement would read a tenant table (a column default, `onupdate` or type `bind_expression` that selects from one) are refused with `SANDLOOM-R018` before anything is sent or flushed. A deferrable unique key is never picked as the conflict key.
  It runs on PostgreSQL and SQLite and refuses a database without `ON CONFLICT`. It returns nothing, and an instance the session already holds keeps its old values until it is refreshed.
  Docs: [Multi-tenancy](docs/modules/database/multi-tenancy.md#insert-or-update-one-tenants-rows), [ADR-0018, decision 6](docs/adr/0018-tenant-guard-at-the-cursor.md).

### Security

- **The cursor guard admits one conflict insert on a tenant table, the one `tenant_upsert` builds** (tenant-upsert-helper).
  The helper marks the statement it runs, and the cursor admits it only when the statement that ran, read from the statement itself and never from the compiled object of its cache key, is an `INSERT` over the table that is, by identity, the `local_table` of a `TenantScoped` mapper, built of exact SQLAlchemy classes, whose SQL equals text for text the SQL of the statement the kernel's one builder (`canonical_tenant_upsert`) writes from the same parts, with the bound tenant in every parameter set and in the `WHERE` of the update. The mark alone admits nothing, counts only at the cursor, and is removed when the call ends. A statement that is refused does not decide for the next one. Every other conflict insert on a tenant table, `DO NOTHING` included, stays refused outside `unscoped()` exactly as before (G-TENANT-27).
  **Upgrade:** code that ran `conflict_insert` on a tenant model inside `unscoped()` to upsert one tenant's rows moves to `tenant_upsert`. It needs a unique key that includes `tenant_id`; a model whose only unique key leaves the tenant out keeps `unscoped()` or gets such a key in a migration.

- **A tenant is compared by its exact type: a `uuid.UUID` subclass whose `__eq__` says yes no longer counts as the bound tenant** (tenant-upsert-helper).
  The flush guard, the cursor guard and the helper accept the bound tenant only as a plain `uuid.UUID` equal to it. A driver's own honest subclass (asyncpg returns one) whose value, `__eq__`, `.int` and `.bytes` all equal the bound tenant is replaced by the plain value before the flush; a subclass that disagrees with itself raises `TenantMismatchError`, and one set after the flush check is refused at the cursor (G-TENANT-25, G-TENANT-26).
  **Upgrade:** none for code that stores `tenant_id` as a `uuid.UUID`, or that reads it from the database. A model that put a `uuid.UUID` subclass of its own, with a custom `__eq__`, into `tenant_id` assigns the plain `uuid.UUID` instead.

### Breaking changes

- **The static rules `cursor-listener` (C039) and the kernel-import rules (C002, C040, C042) catch the mistakes of ordinary code, and the docs now say so** (archcheck-356-accident-only). The rules catch what a module author or an AI agent writes in good faith. A deliberate bypass is not caught statically: this change adds no runtime refusal for a cursor listener or a kernel import, the connection a module opens itself never gets the cursor guard, and row-level security, where enabled, is the boundary. The owner chose this scope on 2026-11-24 (option B) over an allowlist of the forms a registration or an import may take, and the choice is open to review (tm archcheck-revisit-allowed-forms). Guarantees G-TENANT-24, G-TENANT-25, G-TENANT-29 and G-MODULE-02, ADR-0018 decision 8, the multi-tenancy page and the explain texts no longer say "by capability, not by spelling".
  - **C039 cannot be waived.** A `# sandloom: allow cursor-listener <reason>` comment no longer admits a listener, and the message says the comment does not apply. Register a listener outside module code (a driver, the startup, a test), or move a query counter into a test of the module.
  - **C039 sees three more events**: `handle_error`, `after_execute` and `engine_connect` are refused in `event.listen` in module code, because their listeners are handed the raw connection, cursor or result. An ORM session as the target (`event.listen(Session, "close", fn)`) stays allowed, as do the module's own `self.do_execute` and a dict key that spells an event name.
  - **C042 refuses every kernel entry in an application's `allowlist`**: `["sandloom.core"]`, `["sandloom.core.database*"]` and globs such as `sandloom.cor?` too. Only the framework's own tree may excuse one named kernel module under one business module's files. Upgrade: move the import to `sandloom.sdk` and delete the entry.
  - **`sandloom test` fails the architecture check of a root that has no manifest**, where it skipped the check.

### Security

- **The static rules close ten holes that ordinary code could reach** (archcheck-356-accident-only). C039: the event module reached through another sqlalchemy module (`from sqlalchemy.orm.events import event`) and a name or a file imported from another file of the same tree that binds one are followed, one hop (`from .helper import ev`, `from . import event`, `from . import helper` then `helper.ev.listen(...)`, `import pkg.helper as h` then `h.ev.listen(...)`), and the three events above are refused. C037: `conn.connection.cursor()`, `conn.connection.execute(...)`, `session.connection().connection` and a name bound to `<x>.connection` in the same function (`raw = conn.connection`, then `raw.cursor()`), the DBAPI connection and cursor under a connection, are reported; `self.connection.execute(...)` is not. A framework checkout checked with another checkout's environment is still refused by C040, and the message now names that cause. C002: after `import sandloom.sdk`, `import sandloom.shared` or `__import__("sandloom.sdk")`, a read of `sandloom.core.x` as an attribute is reported like the import, and so is `from sandloom import *`; the `sandloom` package object is judged like `sys`, so only `.sdk` and `.shared` stay public. C040: a `sandloom/core` directory made by hand under `modules_path` no longer makes an application the framework's tree, because the check compares resolved paths with the real kernel.
  Upgrade: run `uv run sandloom check` and `uv run sandloom test`. `uv run sandloom explain SANDLOOM-C039` (C037, C002, C040, C042) lists what the rules still do not see: `getattr` on `builtins` or `importlib`, a module `collections` re-exports from `sys`, `exec` and `eval`, a computed `setattr` on the dialect, the closure of a function, the internals of `dispatch`, `runpy` and `pkgutil`.

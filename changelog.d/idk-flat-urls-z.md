### Breaking changes

- **`CACHE_URL`, `BROKER_URL` and the six `CACHE_*` bounds are removed, no alias** (idk-flat-urls-z). Startup refuses each with any value, an empty one included, in the environment and in a `.env` file, and the message names the `INFRA` spelling (`config_tiers.REMOVED`, `inert=None`: no value is inert). `Settings` has no `cache_url`, `broker_url` or `cache_*` attribute and `CacheConfig` is deleted. Every Redis instance states its own `url` in `INFRA` (`cache.default`, `atomic_store.security`, `lease.beat`, `broadcast.default`, `eventbus.default`); the Celery broker is `taskqueue.default.broker`; the client bounds are options of each Redis instance (`socket_timeout_seconds`, `socket_connect_timeout_seconds`, `health_check_interval_seconds`, `max_connections`, `pool_timeout_seconds`, `retry_attempts`) with the defaults the settings had. Upgrade: [Upgrading to 0.7.0a14](docs/operate/upgrade.md). Two cases need care. A staging-like environment whose `INFRA` `cache.default` url differs from `CACHE_URL` must state `atomic_store.security.url` (and `lease.beat`) as the old `CACHE_URL` before upgrading, or the store moves and earlier revocations and blocks are not seen. A rolling deploy with a `broadcast` must state `broadcast.<instance>.url` first.
- **`SettingsFill` has `bounds` and `caps` only** (idk-flat-urls-z). `urls` and `urls_for` are removed (`TypeError`), and `FILLABLE_SETTINGS` is `{"health_check_timeout_seconds"}`: a driver takes no url or client bound from a setting. `sandloom.driverkit.testing_family.FLAT_VARS` is removed with them. A driver package that declared `urls` states the url as an option of its instance, and one that listed `FLAT_VARS` drops it.
- **The harness override reaches `INFRA` only** (idk-flat-urls-z). `SANDLOOM_TEST_CACHE_URL` and `SANDLOOM_TEST_BROKER_URL` are merged into the declared default instances, and into instances on the same Redis server and database as the default (the `url` and `broker` options). An override that matches no declared Redis default instance raises `UnmatchedOverrideError` instead of being dropped. `resolved_cache_url()` reads the resolved `INFRA`, never a flat variable. A parallel run overrides every other declared instance it must not share. The root `.env.test` and `.env.example` declare `INFRA`.

### Security

- **A synthesized instance on the cache's Redis database is a WARNING in production** (idk-flat-urls-z). `InfraProvider.implicit` is `True` only in development: the registry reports no instance as kernel-synthesized in production, so a `lease` or `atomic_store` that shares the cache's database logs the WARNING, not the INFO of a development start.
- **`redis_endpoint` never echoes a password split by `?` or `#`** (idk-flat-urls-z). A url whose path, query or fragment holds an `@` (an unencoded `?` or `#` in the password) gives `None`, so no part of the credential reaches a log line, and a database path of thousands of digits gives `None` instead of raising at startup.

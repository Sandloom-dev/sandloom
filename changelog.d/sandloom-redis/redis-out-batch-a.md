### Changed

- **The Redis harness family implements the three new `HarnessFamily` hooks and owns the per-worker layout** (redis-out-harness). `owns_url`, `same_database` and `parallel_env` carry what the kernel harness knew about Redis url forms, the database 0 default of a url without a path and the `auto` stride of a parallel run. `WorkerLayout`, the stride and the index mapping live in `sandloom_redis.testing.isolation`; the family installs them as the kernel's URL mover. The package needs the kernel that has `sandloom.driverkit.testing_isolation.set_url_mover`: a kernel before this change has no such name and the harness does not start. Upgrade the package with the kernel.
- **A url the package cannot parse no longer leaks its password** (redis-out-harness). The broadcast bus and the Redis test harness read each url through `sandloom.driverkit.url_split.split_url`, so the `ValueError` of a url with a character that NFKC-normalises to `#` (for example U+FF03) carries a fixed message, not the netloc with the password. The options of the cache, atomic store, lease, `streams` event bus and broadcast bus refuse such a url when they are read (a `ValidationError` with one fixed message, the input hidden), so it never reaches `urlsplit` or `redis.from_url`, whose errors quote it. The ownership message answers `<unparseable url>`. The package needs a kernel that has `sandloom.driverkit.url_split`. No other upgrade step.

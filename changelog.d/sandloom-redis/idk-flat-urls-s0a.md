### Changed

- **A `redis` instance with no url is refused at startup, and the message names the INFRA option** (idk-flat-urls-s0a). Opening any of the five Redis drivers (`cache`, `atomic_store`, `broadcast`, `lease` and the `streams` event bus; `aopen`, run by the registry at startup) raises `MissingUrlError` (a `ValueError`, `fatal_at_startup`, so startup aborts in every environment, development included) saying `redis atomic_store instance 'security' has no url: set the INFRA option atomic_store.security.url, e.g. INFRA='{...}'`; it no longer says the kernel fills the url from `CACHE_URL`. A `streams` bus with no url of its own still runs on the default cache client and is refused only when that client has no url either. One helper (`sandloom_redis._settings_fill.require_url`) does the check for all five. Building a provider and a provider built by hand (`create_redis_cache`, a client or client factory passed in) are unchanged.

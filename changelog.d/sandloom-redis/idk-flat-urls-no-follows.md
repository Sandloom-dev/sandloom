### Breaking changes

- **A `redis` broadcast and the synthesized development `atomic_store` no longer follow the url of `cache.default`** (idk-flat-urls-no-follows). Before, a `cache.default` url stated in `INFRA` was also the url of a broadcast that left its own out, and of the development `security` store the kernel synthesizes; now each takes `CACHE_URL` (while it exists) or the url it states itself. Upgrade, by case:
  - An environment whose `INFRA` `cache.default` url differs from `CACHE_URL` (a staging setup): the synthesized `security` store moves to `CACHE_URL` on upgrade. Set `INFRA.atomic_store.security.url` to the old url before upgrading, or revocations and blocks written earlier are not seen.
  - A declared `broadcast` without a `url` now falls back to `CACHE_URL`, not to the `INFRA` url of `cache.default`. During a rolling deploy old and new processes then publish on different Redis servers: set `broadcast.<instance>.url` explicitly first.
  - When `cache.default` has its url in `INFRA` only (no `CACHE_URL`), set `broadcast.<instance>.url` and `atomic_store.security.url` explicitly, or the instance is refused at startup (`MissingUrlError`).

### Added

- **A startup warning when a persistent instance shares the cache's Redis database** (idk-flat-urls-no-follows). A `redis` `atomic_store`, a `redis` `lease` or a `streams` event bus whose `host:port/db` is the one of `cache.default` logs one WARNING naming both instances and the endpoint (never a password): a cache that evicts can drop the keys they must keep. It refuses nothing and does not depend on the order the instances start in. An instance the kernel synthesized (not written in `INFRA`: the development `atomic_store` and the default `streams` bus of a `CACHE_URL`-only start) is logged at INFO instead, so the warning keeps its meaning. The drivers register their endpoints in `sandloom.driverkit.shared_endpoints`, drop them when they close, and a path that still holds an `@` (an unencoded password) is never echoed.

### Fixed

- **A Redis test URL with a `db` query is refused, not left on one database** (redis-isolation-db-query). redis-py reads `?db=N` over the URL path, but the per-worker mover of the test harness, the claim, the allocation and the flush all key on the path index: a URL such as `redis://host:6379/0?db=3` was moved to `/16`, `/32`, ... in the path while every xdist worker still connected to database 3 and the workers shared data. The mover (`worker_redis_url`, `mapped_redis_url`, `moved_redis_url`), `infra_redis_urls` / `redis_urls` (claim, allocation, worker cap) and `slot_bases` now raise a `ValueError` that names the URL (password redacted) and says to put the index in the path. A `?db=` with no value is ignored, as redis-py does. Upgrade: a test `INFRA` url, `SANDLOOM_TEST_CACHE_URL` or `SANDLOOM_TEST_BROKER_URL` that carries `?db=N` changes to `redis://host:port/N`; other query options keep working.
- **`same_database` of the Redis harness family compares servers, not strings** (redis-isolation-db-query). The merge of a `SANDLOOM_TEST_CACHE_URL` / `SANDLOOM_TEST_BROKER_URL` override into the other declared instances treated `redis://Host:6379/1`, `redis://host/1` and `redis://host./1` as three servers, and `?db=3` and `/3` as two databases. It now ignores the case of the host, a trailing dot on it and the implicit port 6379, and reads the database index as redis-py does (a non-empty `db` query wins over the path). Credentials and the other query options still count. No upgrade step: an override that did not reach an instance on the same server before now does.

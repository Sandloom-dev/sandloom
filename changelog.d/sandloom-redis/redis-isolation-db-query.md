### Changed

- **A Redis test URL that names its database any way but `/<digits>` is refused** (redis-isolation-db-query). redis-py reads a non-empty `?db=N` over the URL path, and reads the path with every `/` dropped and percent-escapes decoded (`/3/` and `/%33` are database 3, `/1/5` is 15, a path that is no number is 0). The per-worker mover of the test harness, the claim, the allocation and the flush read only a plain `/<digits>` path. A URL such as `redis://host:6379/0?db=3` was moved to `/16`, `/32`, ... in the path while every xdist worker still connected to database 3 and the workers shared data; `redis://host:6379/3/` was left unmoved, and every worker shared database 3. The mover (`worker_redis_url`, `mapped_redis_url`, `moved_redis_url`), `infra_redis_urls` / `redis_urls` (claim, allocation, worker cap) and `slot_bases` now raise a `ValueError` that names `scheme://host:port` and the reason, never the path, the query or a password. The `SANDLOOM_TEST_CACHE_URL` and `SANDLOOM_TEST_BROKER_URL` overrides go through the same checks. A `?db=` with no value is ignored, as redis-py does. Upgrade: a test `INFRA` url or override that carries `?db=N` or a path other than `/<digits>` changes to `redis://host:port/N`; other query options keep working. A `redis:///path` socket-style URL is refused too (redis-py would use database 0 on the local host); use `redis://host:port/<index>`.
- **`same_database` of the Redis harness family compares what the connection uses** (redis-py reads one database). The merge of a `SANDLOOM_TEST_CACHE_URL` / `SANDLOOM_TEST_BROKER_URL` override into the other declared instances now takes the server and database from `sandloom.driverkit.shared_endpoints.redis_endpoint`, the one reader of them (host lower-cased, port 6379 when left out, the database as redis-py reads it: a `db` query wins over the path, the path loses every `/` and its percent-escapes, and a path that is no number is database 0). Credentials, the scheme and the other query options still count. A host with a trailing dot stays a different host from the one without (an absolute name against one the resolver may complete). A URL that names no endpoint (a bad port, an unencoded `/` in the password, an unbracketed IPv6 host) is no longer an error that could quote its start: `same_database` answers `False`. `redis_endpoint` itself now lets a non-empty `?db=` win over the path, as redis-py does (the shared-database startup warning followed the path), and `sandloom.driverkit.shared_endpoints.DEFAULT_REDIS_PORT` is public. Upgrade: an override URL that names a database as `/x` (redis-py: database 0) now matches `/0`.

### Changed

- **`sandloom add module` and `add event` take `--no-tenant` for an app without tenants** (dogfood-cli-generators). The scaffold stays tenant-scoped by default: a `TenantScoped` table with row-level security, and a `tenant_id` on every event. Nothing is read from the environment, `.env` or `SECRETS_DIR` to decide it, because a gitignored `.env` differs per machine and would scaffold a table without row-level security into an app that is multi-tenant in production. `--no-tenant` is the explicit choice: `add module` writes a plain `Base` table with no `tenant_id`, no row-level security and tests that call `as_user(tenant=False)`, and `add event` adds no `tenant_id` unless you name it with `--field`. The flag exists on `module` and `event` only; `add projection` is unchanged, and a projection row always carries `tenant_id`. `sandloom new` still writes its sample module tenant-scoped. Upgrade: none; an app without tenants passes `--no-tenant`.
- **`sandloom generate` removes the exported schema of an event its module no longer declares** (dogfood-cli-generators). Deleting or renaming an event class left `<shared>/events/<channel>.json` behind for good. `generate` now removes that file with the same mechanism it uses for stale consumer copies and prints `removed <path>`; `generate --check` lists it as stale (an orphan), so `sandloom test` fails until the file is gone. A released event is not an exception: a name that is gone loses its mark and its file. Only a module the process composed can orphan a schema: the files of a module that is not composed (a `SANDLOOM_MODULES` subset, an optional module that did not load, a module deleted whole) stay, and so do all files when you name modules (`sandloom generate <module>`). Only a file named like a channel (`<module>.<name>.vN.json`) can be an orphan: any other JSON kept in `shared/events` is never removed or reported. The removed file never appears in `.sandloom/inspection.json`. Upgrade: none; commit the removal.
- **Every `sandloom add` generator and argument has help text** (dogfood-cli-generators). `sandloom add --help` lists each generator with a summary, and each `--help` names every argument. `--field` is shown as `NAME:TYPE`, lists the accepted types (`str`, `int`, `float`, `bool`, `UUID`, `datetime`, `date`, `Decimal`) and says it repeats. `sandloom new --help` ends with a line for framework contributors that points to the contributing setup page; the `--framework-*` flags stay hidden.

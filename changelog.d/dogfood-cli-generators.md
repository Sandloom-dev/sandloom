### Changed

- **`sandloom add module` and `add event` follow the app's `TENANCY_MODE`** (dogfood-cli-generators). The scaffold was always `TenantScoped` with row-level security, and every event got a `tenant_id`, so an app without tenants had to strip them by hand. The generators now read `TENANCY_MODE` the way the app does and without booting it (process environment, then `.env`, then `SECRETS_DIR`; `multi` where none names it). With `TENANCY_MODE=single` (the mode for an app without tenants) `add module` writes a plain `Base` table with no `tenant_id`, no row-level security and tests that call `as_user(tenant=False)`, and `add event` adds no `tenant_id` unless you name it with `--field`. `multi`, the default, writes the same files as before, byte for byte. A value other than `multi` or `single` is refused and names where it came from. `add projection` is unchanged: a projection row always carries `tenant_id`. Upgrade: none for `multi` apps. A `single` app that wants a tenant on a new event passes `--field tenant_id:UUID`.
- **`sandloom generate` removes the exported schema of an event its module no longer declares** (dogfood-cli-generators). Deleting or renaming an event class left `<shared>/events/<channel>.json` behind for good. `generate` now removes that file with the same mechanism it uses for stale consumer copies and prints `removed <path>`; `generate --check` lists it as stale (an orphan), so `sandloom test` fails until the file is gone. A released event is not an exception: a name that is gone loses its mark and its file. Only a module the process composed can orphan a schema: the files of a module that is not composed (a `SANDLOOM_MODULES` subset, an optional module that did not load, a module deleted whole) stay, and so do all files when you name modules (`sandloom generate <module>`). The removed file never appears in `.sandloom/inspection.json`. Upgrade: none; commit the removal.
- **Every `sandloom add` generator and argument has help text** (dogfood-cli-generators). `sandloom add --help` lists each generator with a summary, and each `--help` names every argument. `--field` is shown as `NAME:TYPE`, lists the accepted types (`str`, `int`, `float`, `bool`, `UUID`, `datetime`, `date`, `Decimal`) and says it repeats. `sandloom new --help` ends with a line for framework contributors that points to the contributing setup page; the `--framework-*` flags stay hidden.

### Changed

- **`CACHE_URL` and `BROKER_URL` are optional settings** (idk-flat-urls-s0a). Neither is required to start: an app that selects no Redis or Celery driver (the `memory` and `database` stacks) starts with both unset, and `sandloom` no longer lists them among the missing service URLs of a new app (`DATABASE_URL` is the one left). Set, they are still accepted, still must start with `redis://` or `rediss://`, and still fill the `url` / `broker` / `backend` option of a driver instance that states none, so no configuration breaks. An unset one gives no option (never a `None` one), and a backup plan or beat-lease scope no longer reads a missing url. The way to configure them is the driver option in `INFRA` (`cache.default.url`, `taskqueue.default.broker`); the flat settings go away in a later release. `Settings.cache_url` and `Settings.broker_url` are `str | None` now.
- **A failure that carries `fatal_at_startup` now aborts a development startup** (idk-flat-urls-s0a). The infra warm-up startup task was critical only in production, so in development the `InfraStartupError` it raised for such a failure (a Redis instance with no url, an application role that could escape tenant RLS) was logged and the app went on; it is critical in every environment now (`aopen_all` raises in a non-strict startup only for those failures, so an unreachable backend still only warns in development). The backup plan places an event bus with no url at the url of `cache.default` (INFRA) before `CACHE_URL`.

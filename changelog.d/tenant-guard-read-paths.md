### Security

- **The legacy `Session.bulk_*` methods bypassed the tenant guard** (tenant-guard-read-paths). `Session.bulk_update_mappings` rewrote another tenant's row by primary key, and `bulk_insert_mappings` / `bulk_save_objects` planted rows with any `tenant_id`, because they run neither the ORM-execute guard nor the flush ownership check. **Behaviour change:** all three are now refused with `UnsafeTenantOperationError` on a `TenantScoped` model (or any mapper over its table) unless inside `unscoped()`, with or without a bound tenant. Use ORM instances (`session.add`), or wrap a trusted system import in `unscoped()`. The same calls on a model that is not `TenantScoped` are unchanged.
- **Another tenant's rows could be read or copied through SQL a statement hides** (tenant-guard-read-paths). Under a bound tenant, `with_expression(...)`, `with_loader_criteria(...)`, the extra criteria of `selectinload(Parent.children.and_(...))`, `insert(Other).values(...)` (dict, keyword arguments and multi-row), and a bare `func.f(select(...))` executable read other tenants' rows, because the guard looked only at what `get_children()` lists and skipped every statement that is not a select, insert, update or delete. The guard now reads loader-option expressions and `VALUES` rows, and runs for every statement except `text()`. **Behaviour change:** a `with_expression` subquery and a bare function that reach a `TenantScoped` table are refused with `UnsafeTenantOperationError` (`MissingTenantError` with no tenant bound) outside `unscoped()`, and a SQL-expression column `default=` / `onupdate=` that reads a `TenantScoped` table on a table that is not tenant-scoped is refused on an INSERT/UPDATE statement and at flush. Subqueries in loader criteria, relationship `and_(...)` and `values(...)` that go through a `TenantScoped` model are scoped to the bound tenant; a raw `Table` reference there is refused. Set a default value in Python, or wrap the write in `unscoped()`.
- **The tenant guard now sits at the cursor, not only in the statement walk** (tenant-guard-read-paths, ADR-0018). Three red-team rounds kept finding SQL that reaches the cursor without the ORM guard seeing it: `session.connection()` Core calls, a `ctx.connection` call in a column default, a `Table` of another `MetaData`, a `@compiles` element, a flush of a forged instance, an identity-map hit, a `secondary` or `column_property` over a raw tenant table, a caller-supplied value for the tenant criterion parameter. The cursor of every engine the framework builds now refuses, outside `unscoped()`, any compiled statement that names a `TenantScoped` table, matched by name with the schema ignored, unless the ORM guard approved that very statement or it is a flush write of rows the unit of work verified. The refusal is `UnsafeTenantOperationError` under a bound tenant and `MissingTenantError` with none. **Behaviour change:**
  - Core on `session.connection()` or an engine over a tenant table is refused, because no ORM execute guard approved it. Run ORM statements over the entity through `session.execute`, or wrap trusted system access in `unscoped()`. A `text()` passed straight to `session.execute` is unchanged and stays the caller's responsibility.
  - **Upgrade: DDL over a tenant table runs in `unscoped()`.** A `DDL(...)` element, `metadata.create_all` / `drop_all` and index creation name the table, so the cursor refuses them outside `unscoped()`. `ensure_model_schema` and the test harness's schema reset do this already. A test fixture that creates or drops the tables of a tenant model wraps its DDL in `with unscoped():`. The `unsafe-tenant-sql` check (`SANDLOOM-C015`) now flags `DDL(...)` outside `unscoped()` like `text()`.
  - The scan of a raw fragment (`text()`, `literal_column()`, a `DDL()` string) counts every bare word whatever its quoting. A literal or a comment that spells a tenant table's name is refused as reaching it, and a PostgreSQL `U&"..."` identifier counts as every tenant table.
  - A flush write is an allowlist: an INSERT must carry an explicit `tenant_id` equal to the bound tenant, and an UPDATE or DELETE must name a row, by primary key, that the unit of work verified in that flush. A statement that a column default or a listener wrote on the flush connection is refused.
  - The load of a deferred or expired column, and the flush UPDATE or DELETE of an instance, are refused for an instance with no stamp of the bound tenant: one built by `merge(load=False)`, unpickled, or passed through `make_transient_to_detached`, or loaded by a `load_only()` / `defer()` projection that left out `tenant_id`. Load it first (include `tenant_id` in the projection), or wrap the write in `unscoped()`. The stamp of an inserted instance is set when the flush succeeded and cleared when its transaction rolls back.
  - `Session.get`, `get_one` and a many-to-one lazy load return an identity-map instance only when it carries the bound tenant's stamp, and run the scoped query otherwise. With no tenant bound they raise `MissingTenantError`.
  - A statement that carries the tenant criterion parameter itself, in its execution parameters or from a later listener, is refused, and a statement a later `do_orm_execute` listener replaced carries no approval.
  - A mapper whose `column_property` or `secondary` reads a raw tenant table refuses a bound statement over it that also reaches a tenant table; read the table through its mapped entity instead.
  - A same-named table in another schema is refused as a tenant table.
  `Connection.exec_driver_sql` has no compiled statement and is not checked; row-level security stays the strong boundary. Also not checked: a `text()` sent straight to `session.execute`, a column load of a stamped instance with no tenant bound, the guard's private state and private SQLAlchemy APIs.

### Changed

- **`sandloom check` rules `yield-inside-unscoped` and `engine-in-module` are stricter** (tenant-guard-read-paths). `SANDLOOM-C036` accepts `unscoped` in a module only as the direct item of a `with` (`unscoped()` is synchronous: no `async with`) and reports a `yield` inside it, or in a later item of the same `with`, with no decorator exemption. `SANDLOOM-C037` follows a name bound to a constant `importlib.import_module("sqlalchemy")` / `__import__("sqlalchemy")`. **Behaviour change:** a `@contextmanager` / `@asynccontextmanager` wrapper around `unscoped()` is now reported, as is every alias, variable, argument, decorator, `ExitStack.enter_context`, `functools.partial` and `getattr` use. `SANDLOOM-C037` now lists capabilities, not constructor spellings: an engine or pool factory or class, a star import from `sqlalchemy`, `sqlalchemy.pool`, `sqlalchemy.engine` beyond `CursorResult`, `Result`, `Row`, `RowMapping`, `Connection`, `URL` and `make_url`, a DBAPI driver import (`sqlite3`, `psycopg`, `asyncpg`, `aiosqlite` and kin), `raw_connection()` and an engine's `.pool`.

### Added

- **`sandloom check` rules `yield-inside-unscoped` and `engine-in-module`** (tenant-guard-read-paths). `SANDLOOM-C036` keeps the tenant bypass inside its `with` block and `SANDLOOM-C037` keeps a business module on the framework's engine, whose cursor carries write admission and the tenant check. Upgrade: read inside the `with unscoped():` block and yield after it, write `unscoped()` only as a `with` item, and take the database from the module's session, which a driver built from `INFRA`.

### Added

- **`sandloom.driverkit.url_split.split_url`** (redis-out-harness). `urlsplit` for a url a person typed: the stdlib raises a `ValueError` that quotes the netloc, password included, when it holds a character that NFKC-normalises to `:`, `/`, `?`, `#` or `@` (for example U+FF1A). `split_url` raises one fixed message and drops the chained error. The kernel's production profile, the consumer runtime's database url identity, the `sandloom dev` and wizard url parsing, the test harness, the Redis package's url handling and the Celery task queue's `isolation_identity` use it (the kernel implementation is `sandloom.core.url_split`, a module that imports nothing of the kernel); the redaction helpers answer `<unparseable url>`. A driver package imports it from `sandloom.driverkit`. This covers the kernel harness, `sandloom dev` and the production profile, `sandloom-redis` and the Celery task queue only. Two other places still call `urlsplit` on a url that can hold a password and are not fixed here: the Celery connection policy (`connection_policy.py`, fixed by PR #317) and the `sandloom backup` url handling in `migrations/backup.py` (tm task `backup-urlsplit-secret-leak`).
- **Three hooks on `HarnessFamily`** (redis-out-harness). A harness family now also says which URLs it owns (`owns_url(url)`), whether two of its URLs name the same database (`same_database(stated, base)`) and which environment a parallel run needs (`parallel_env()`). `sandloom.driverkit.testing_isolation` gains `set_url_mover(family, mover)`: each family installs its own function `(url, worker number) -> url` under its name (installing again replaces it, `None` removes it), and `isolated_url_options` applies every installed mover in turn to each URL option of a worker `gw<N>`; a mover returns a URL it does not own unchanged. With no mover installed the options are unchanged. `sandloom.driverkit.testing_family`, `testing_isolation` and `url_split` are now in the public API baseline.

### Changed

- **The test harness names no backend** (redis-out-harness). The worker rewrite, the claim of a slot's resources, the same-database check of an override and the xdist environment of `sandloom test` read the installed harness families, not a Redis url form. A `SANDLOOM_TEST_CACHE_URL` or `SANDLOOM_TEST_BROKER_URL` that no installed family owns is refused with `UnmatchedOverrideError`, as before for a URL that matches no INFRA instance. The message now reads "INFRA declares no URL of an installed backend". The override value is checked as well, not only the URL `INFRA` declares: a value that is no URL of an installed backend (`unix:///tmp/r.sock`, `memcached://h`) is refused with a message that does not quote it. Upgrade steps: none for an app on the standard stack.
- **The `sandloom_cache` and `real_uow_client` fixtures take the cache driver from the app or from `INFRA`** (`cache.default.driver`), not from the name `redis`. A project that configures no cache driver fails with a `RuntimeError` that says so: `fixtures._cache_driver` has no `redis` fallback. The fixture that points the implicit `security` store at the test cache (`_security_store_on_cache`) overrides it only when its driver equals the cache driver.
- **`RedisFamily.parallel_env()` returns `{}` when the `redis` client is not installed** (redis-out-harness): a parallel `sandloom test` of an app with no Redis client sets no `SANDLOOM_TEST_REDIS_DB_STRIDE`.

- **`sandloom test` runs `ruff check --no-fix` in every mode** (redis-out-harness). Developer mode used to run `ruff check` first and let a project's `fix = true` rewrite source, which `sandloom test` otherwise never does (it only checks the generated files). It now reports a violation and fails; run `uv run ruff check --fix` yourself. The step moves from first to the static gates (after the tests), as `--ci` already had it, and `--ci` now differs from the default only in not recording route effects. Every `sandloom new` app sets `fix = true`, so a violation the gate used to fix silently now fails the run once. The quality-gates skill, `docs/reference/cli.md` and `docs/ai/checks.md` say so.

### Fixed

- **The same-server check of the production profile sees `host.` as `host` and a unix socket by its path** (redis-out-harness). A store url spelled with the fully-qualified host (`redis://cache.:6379`) was a different server from `redis://cache:6379`, and a unix-socket url (`unix:///run/cache.sock`, `<driver>+unix://...`) was never the same server as anything, so `security` and `idempotency` stores could share the cache server's socket past the refusal. Both now compare equal: the host without its trailing dot, the socket by its normalised, percent-decoded path whatever the driver prefix and whatever host the url states (`unix://localhost/run/r.sock` is `unix:///run/r.sock`). A deployment that relied on the gap is refused at startup with the existing message. No other upgrade step.

- **`sandloom test` fails one step, with its message, when the composition root is malformed or the settings refuse to load** (redis-out-harness). The migration drift step resolves `SANDLOOM_COMPOSITION_ROOT` just before it starts; a `CompositionRootError` or a `SystemExit` from the settings used to end the whole run with a traceback or a bare exit. It is now that step's failure (`sandloom test: <step>: <message>` on stderr, exit 1) and the other steps still run. No upgrade step.

### Breaking changes

- **`sandloom.driverkit.testing_isolation.isolated_redis_options`, `WorkerLayout`, `DEFAULT_STRIDE`, `set_worker_layout` and `worker_layout` are removed** (redis-out-harness). A driver package calls `isolated_url_options(options, worker_id, keys)` instead, and a harness family installs its layout with `set_url_mover(family, mover)`; the layout of a Redis index per worker now lives in `sandloom_redis.testing.isolation`. No alias (ADR-0010).
- **`sandloom.core.testing.workers.REDIS_VARS` is now `URL_VARS`, and `Slot.redis_urls` is now `Slot.family_urls`** (redis-out-harness). Upgrade: rename both in a test helper that reads them. `SANDLOOM_TEST_REDIS_DB_STRIDE` keeps its name: it is the Redis family's own variable.

### Changed

- **The CLI talks plainly** (dx-cli-help-noise). A command that runs once (`migrate`, `add`, `generate`, `test`, `check`, `doctor`, ...) logs warnings and errors only: the `claim authorities` line and the alembic INFO lines are gone, so `migrate new` ends on `Created <file>`. `sandloom -v <command>` (before the command) brings the INFO lines back; an exported `LOG_LEVEL` wins, and `dev`, `worker` and `beat` keep the configured level. `sandloom --help` groups the commands into `start`, `build` and `operate`, and `admin` says what it does (`create`, `invite`, `list`, `export`). `sandloom new --yes` without `--agents` now writes only the shared `.agents/skills` folder and `AGENTS.md` (it used to write a copy for every installed agent and a pointer file per agent); pass `--agents claude` for `CLAUDE.md` and `.claude/skills`. `new --services none` no longer lists `dev up` in "Next steps". The help of `new` and `dev up` says Redis, not "keyed server". The glossary counts 26 beginner names (20 and six test helpers) and lists `admin` among the standard modules. `sandloom explain` texts no longer cite internal specs or a `tests/fixtures/specs` path, and the texts of `SANDLOOM-C031`, `C033` and `B037` lead with the cause and the fix. This changes what a new project gets, so the DX eval is the owner's to rerun. Upgrade: a script that relied on the INFO lines or on `new --yes` writing `CLAUDE.md` passes `-v` or `--agents claude`.

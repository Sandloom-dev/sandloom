### Security

- **`sandloom backup plan` and the migration logs mask every secret of a url** (idk-low9). `_mask_url` hid the credentials of a plain `scheme://user:password@host` only: a `?password=` query value, the second password of a `;`-separated kombu broker list and the tail of a password holding a raw `@` were printed in full (the plan's Redis targets, the `pg_dump` line, the migration lock messages and `sandloom extract`). It now splits a broker list only at a `;` that starts another `scheme://` (a `;` inside a password stays in it), masks each url on its own, ends the userinfo at the last `@` of the url and hides the value of every query parameter whose name ends in `password`, `passwd`, `pass`, `pwd`, `secret`, `token`, `key`, `sig`, `signature`, `auth` or `credential(s)` (`sslpassword`, `access_token`, `client_secret`, ...), after a `?`, an `&` or a `;`. The `error` of a database in `sandloom migrate status` is masked with the same masker, the whole userinfo as before (`scheme://***@host`). That masker is `sandloom.core.migrations.url_mask.mask_url_credentials`, the one of `sandloom config` and `sandloom doctor` (`sandloom.core.cli.url_text` re-exports it): it still keeps a user name (`scheme://user:***@host`) but now hides it too when the password is empty or `x-oauth-basic`, where the user slot holds a token or a key, and it masks the secret-named query parameters above. No upgrade step.
- **A `TRACING_URL` or a `SERVICE_BINDINGS` `base_url` that `urllib` cannot parse no longer echoes its password** (idk-low9). A netloc character that Unicode-normalizes to `:` `/` `?` `#` or `@` (U+FF1A, say) makes `urlsplit` raise a `ValueError` whose message carries the whole netloc, `user:password` included, and the settings validation error copied it. The validators now raise a fixed message. A url with such a character was refused before and is refused now; only the message changes.

### Fixed

- **A removed setting is matched with the case fold pydantic uses** (idk-low9). The check that refuses a removed setting (`EVENT_BUS_REDIS_SEMAPHORE_LIMIT`, `CACHE_URL`, ...) folded names with `upper()` while pydantic-settings folds with `lower()`, so an environment name holding U+017F (`event_bus_redis_ſemaphore_limit`, which `upper()` turns into `...SEMAPHORE...`) was refused as the removed setting though no setting of that name is read. It compares with `lower()` now; every name that was refused with an ASCII spelling still is.
- **The `generate --check` step of CI no longer sets `SANDLOOM_COMPOSITION_ROOT`** (idk-low9). Since PR #314 the project names the composition root of `sandloom generate` (`[tool.sandloom] composition-root` in `pyproject.toml`), so the variable only repeated that key. `tests/architecture/test_ci_workflow_policy.py` asserts that the step names none.

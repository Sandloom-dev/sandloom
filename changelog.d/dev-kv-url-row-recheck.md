### Fixed

- **`sandloom dev up --services external --kv-url URL` compares servers by host and port, not by text** (dev-kv-url-row-recheck). A row's two Redis indexes are checked empty on the keyed server of their time, and `dev reset` / `dev prune` flush them. When `up` names another server, every row's pair is checked again there: a pair that holds keys is replaced, and the `up` is refused before the state is saved when the server has no two empty indexes. Whether the server changed was decided on the address text, so the same server written with a trailing dot on its host (`redis://host.:6379`) was a change and the pair was moved or the `up` refused for nothing. The host's case, a trailing dot on it and the default port 6379 no longer tell two URLs apart. A different host or port still triggers the check. The tests now cover the same server (no re-check), another server with free indexes (state updated), and another server without room (refused, state and keys untouched). No upgrade step.

### Changed

- **The DLQ replay ids and the DLQ listing cursor of the admin API are opaque tokens** (idk-low5-product). `POST /api/v1/platform/<module>/streams/replay` (`ids`) and `GET .../streams/dlq` (`cursor`) took only a Redis stream id (`^[0-9]+-[0-9]+$`), so an event transport with UUID ids answered 422 on replay and from the second page on. They now take `^[A-Za-z0-9_.:-]{1,80}$`; a Redis stream id still matches. The admin console's exported contract (`admin/contracts/openapi.json`) carries the new pattern. No upgrade step.
- **`sandloom worker check` on an install that cannot answer exits 1 with the refusal, not a traceback** (idk-low5-product). A lean install without the taskqueue driver (SANDLOOM-B037) or an `INFRA` with no taskqueue instance prints the code and the fix on stderr. Any other failure still raises.
- **`sandloom dev up` reads the composition in a child that finds the checkout's package under `PYTHONSAFEPATH=1` and ignores what the app prints** (idk-low5-product). The answer is the line that carries a sentinel prefix, so a banner printed at import or at exit no longer breaks the read.
- **`sandloom dev up` writes `SANDLOOM_TEST_CACHE_URL` / `SANDLOOM_TEST_BROKER_URL` only where the harness can apply them** (idk-low5-product). The decision reads the `INFRA` of the checkout's `.env.test` (the one the harness merges them into) next to the composition's selection: a name is written only for a capability whose `default` instance declares a Redis url there, so an app whose `.env.test` has no task queue url no longer gets an override that stops every test run with `UnmatchedOverrideError`. A `.env.test` with no `INFRA` keeps the selection's decision. The capability map is the harness's own, `sandloom.core.testing.workers.INFRA_URL_CAPABILITIES` (was the private `_INFRA_URLS`).
- **The `redis` event bus is no longer documented** (idk-low5-product). No driver registers it (the Redis package registers `eventbus.streams` only): the event bus page, the infrastructure index and the driver guide name `streams` and `memory`.
- **The README's SQLite `INFRA` line and the tutorial's `INFRA` example name every Redis instance** (idk-low5-product), and a test holds the README line to `DEFAULT_INFRA`.
- **The production benchmark stand states its security store as `atomic_store.security`** (idk-low5-product), where it had `cache.security`: the stand now has a security store and the tail probe labels its Redis.

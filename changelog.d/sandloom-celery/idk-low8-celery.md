### Breaking changes

- **An `sqs://` broker url with a host the driver cannot read a region from is refused** (idk-low8-celery). The queue-url pin reads the region out of the `INFRA` host, so a host with a trailing dot (`sqs.eu-west-1.amazonaws.com.`), a percent escape or a non-ASCII character (kombu decodes `%2E` or U+3002 into a real AWS host), the legacy `<region>.queue.amazonaws.com`, the dual-stack `sqs.<region>.api.aws` and `sqs-fips.<region>.amazonaws.com.cn` (the China regions have no FIPS endpoint) left the pin silently off. The `celery` taskqueue options now refuse each at startup, naming the option and no url. Upgrade: use `sqs.<region>.amazonaws.com`, the `sqs-fips.<region>.amazonaws.com` name (outside China) or a `vpce-<id>.sqs.<region>.vpce.amazonaws.com` interface endpoint. An emulator or proxy host without a trailing dot is still accepted. A queue `url` of a config module on `sqs-fips.<region>.amazonaws.com.cn` is refused too.

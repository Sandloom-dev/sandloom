### Changed

- **`celery -A sandloom_celery.worker` reads its broker from `INFRA`, not from the `BROKER_URL` variable** (idk-flat-urls-c). The importable app (`app`, `celery`, `celery_app`; for `celery inspect`, `call`, `status` and Flower) is built, on first use and with no import side effect, from the options of the `default` task queue as the application resolves them: `Settings` (environment and `.env`), the composition's selection, `INFRA` over it. State the broker as `INFRA='{"taskqueue":{"default":{"broker":"redis://..."}}}'`. Without one the lookup raises `AttributeError` naming `taskqueue.default.broker`, and a `default` task queue that is not the `celery` driver is refused with a message saying so. The module no longer reads `os.environ["BROKER_URL"]` (`BROKER_URL_ENV` is removed). A stray `BROKER_URL` in the environment still cannot replace the broker of a worker or a beat: `sandloom worker` and `sandloom beat` keep hiding Celery's own `BROKER_URL` option variable for the run. The importable app is stricter than before about the same variables: Celery's CLI writes `CELERY_BROKER_URL` from `-b` / `BROKER_URL` and `CELERY_RESULT_BACKEND` from `--result-backend` / `RESULT_BACKEND`, and `app.conf` prefers them over the app's own broker, so the app raises `AttributeError` naming the variable (never its value) when `CELERY_BROKER_URL`, `CELERY_BROKER_READ_URL`, `CELERY_BROKER_WRITE_URL` or `CELERY_RESULT_BACKEND` is set to something other than what `INFRA` states. A value equal to `INFRA`'s, or a blank one, passes. The app also compares its finished `app.conf` (`broker_url`, `broker_read_url`, `broker_write_url`, `result_backend`) with `INFRA` and raises `AttributeError` naming the option when one differs, because a config module (`celery --config X`, `CELERY_CONFIG_MODULE`) or the default loader (`--loader default` imports `celeryconfig.py` from the working directory) can set a write broker or a result backend that the environment check does not see; the check also runs when the provider built the process-wide app first. Upgrade: a service that ran `celery -A sandloom_celery.worker ...` with only `BROKER_URL` set (and no `INFRA`) keeps working while the flat `BROKER_URL` setting exists, because the kernel still fills the broker from it; the setting goes away in a later release, so put the broker into `INFRA` now.
- **`backend` has no default and is documented as optional** (idk-flat-urls-c). Sandloom never reads a task result (`task_ignore_result` is on), so an instance that states no `backend` runs with no result backend. The kernel still fills a missing `backend` from `CACHE_URL` until that setting is removed in a later release: leave `backend` out of `INFRA`, and do not rely on the fill. The importable app now takes the same `backend` as the provider's `default` instance (before: always none).
- **The importable app needs the kernel's configuration to be valid.** Reading `INFRA` loads `Settings`, so an invalid configuration (for example a missing `DATABASE_URL`) stops `celery -A sandloom_celery.worker` with the configuration error, where it used to start from `BROKER_URL` alone.

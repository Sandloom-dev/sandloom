### Changed

- **The tenant selection errors carry a `code` and say what to do** (tenant-select-and-dev-verify). `TenantScope` answers a request with no tenant `400` with `code` `tenant_required` and a `detail` that names the header the route reads and says its value is an organization id that the access token lists. It answers an organization the token does not list `403` with `code` `tenant_not_authorized` and a `detail` that names the header and says to refresh the access token or log in again when the user joined or created the organization after the token was issued. A `MissingTenantError` at the request boundary answers the same `400` (its text says "the tenant header"). The HTTP statuses are unchanged; the `detail` text is part of the API, so a client that compared it with `tenant context required` or `tenant is not authorized by the access token` compares the `code` now. The kernel text names no module route. See "Upgrading to 0.7.0a16: tenant selection errors carry a code and say what to do" in `docs/operate/upgrade.md`.
- **`POST /api/v1/orgs` derives `slug` from `name`** (tenant-select-and-dev-verify). `slug` is optional: lowercase, every run of characters outside `a-z0-9` becomes one `-`, trimmed and cut to 100 characters. A derived slug that is taken answers `409` asking for `slug`; a name with nothing to derive from answers `422`. An explicit `slug` is validated as before.

### Added

- **Identity prints the API form of the e-mailed steps in dev** (tenant-select-and-dev-verify). With `NOTIFIER_LOG_LINKS=true`, registration and resend print `[dev only] no frontend? POST /auth/verify-email {"token": "..."}` and a password reset request prints the `POST /auth/reset-password` form on stderr after the change commits, so an app without a frontend can finish the step. Nothing is printed without the setting (refused in production without the accepted risk `log_links_in_prod`); no setting verifies an account by itself.

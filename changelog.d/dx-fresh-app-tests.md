### Changed

- **The pytest plugin never reads the developer's `.env`** (dx-fresh-app-tests). A test run is composed of the shell, `.env.test`, `.env.test.local` and `SANDLOOM_TEST_*`, in that precedence (one table in `docs/modules/testing.md`, "What a test run reads"). Before, a key only your dev `.env` set (`TENANCY_MODE=single`, a storage path, a composition root) reached the tests and changed their result. `sandloom migrate`, the authoring commands and the non-pytest steps of `sandloom test` still read `.env`: they run your app. Upgrade: a test that relied on a dev `.env` value puts it in `.env.test`, which `sandloom new` already writes.
- **The `SANDLOOM-R014` line tells you what to start after `dev up --services external`** (dx-fresh-app-tests). It said "Start the dev services: uv run sandloom dev up" even where `dev up` starts nothing. It now adds "with --services external it starts nothing: start <the backend at host:port> yourself". A backend named by URL in a harness message gives its host and port, never a credential.

### Fixed

- **A plain `uv run pytest` right after `sandloom migrate new` runs instead of refusing the app's own test database** (dx-fresh-app-tests). `migrate new` creates the test database before any run holds a slot and stamps it with the checkout alone (`<machine>:<checkout>`); the first pytest is slot 1 of that checkout (`…#1`) and was refused as another run. A slot run now owns its own checkout's slot-less database, as long as no run has used it yet (`migrate new` stamps it without the `sandloom_test.last_used` setting that every claim writes). A slot-less database a run already claimed, which may be a live run that got no slot, is refused to a slot run; `SANDLOOM_TEST_TAKE_OWNERSHIP=1` takes it once it is gone. A database of another checkout, machine or slot is still refused, and an owner id you set yourself (`ci:shard#2`) is never cut.
- **The false `UserWarning` "settings imported before .env.test was loaded" is gone** (dx-fresh-app-tests). Importing the settings reads nothing since they became lazy, but the warning fired on the module being imported, which the plugin's own imports cause. It fires only when the settings were actually loaded earlier, and names one fix: list `-p sandloom.sdk.testing.plugin` first in `addopts`.
- **`as_user` (and `make_user_headers`) mints into `SINGLE_TENANT_ID` under `TENANCY_MODE=single`** (dx-fresh-app-tests). It picked a random tenant, so every request of a fresh single-tenant app answered `403 tenant_mismatch`. A `tenant_id` the test names is kept, so a test can still assert the refusal. Multi-tenant apps are unchanged.
- **A test run with no Redis exits with one `SANDLOOM-R014` line instead of an INTERNALERROR traceback** (dx-fresh-app-tests). The controller's allocation of the workers' Redis indexes now maps a Redis that does not answer (a refused connection, a timeout, a socket error) onto `Unavailable`, and the session ends with the usual usage-error exit naming the server. A server that answered with an error is not an outage and keeps its traceback.

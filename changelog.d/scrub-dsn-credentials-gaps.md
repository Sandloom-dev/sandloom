### Security

- **The log and Sentry scrubber hides a url's whole userinfo and its secret query values** (scrub-dsn-credentials-gaps). `scrub_text` (`sandloom.core.observability.guardrails`) matched `scheme://user:password@` with a password that holds no `/`, `@` or space, so a password with a raw `@` (`postgresql://u:p@ss@h/db` printed `***@ss@h/db`), an unencoded `/` or a space was printed in part, and the value of a `?password=ab;cd` or `)`-holding query parameter kept its tail; a `?sig=`, `?key=` or `?auth=` value was not masked at all. The userinfo now runs from `scheme://` to the last `@` of the line, without crossing another `scheme://`, and the value of a query parameter whose name ends in `password`, `passwd`, `pass`, `pwd`, `secret`, `token`, `key`, `sig`, `signature`, `auth` or `credential(s)` is masked up to the next `&`, `#` or space; a `;` in the value is part of it, also one that starts `x://`, so `?password=a;redis://h2/0` prints `?password=***` (the scrubber printed `;redis://h2/0` before). A line that holds a later `@` after a url (a mail address) is masked too far, never too short. `scheme://user@host` without a password now prints `scheme://***@host` too, since the user slot may hold a token. No upgrade step.
- **One masker for the scrubber, `sandloom config`, `sandloom doctor` and the migration logs** (scrub-dsn-credentials-gaps). The url patterns live once, in the new leaf module `sandloom.core.url_mask` (on the bottom layer of the kernel layers contract, so `observability`, `migrations` and `cli` all import it). It was `sandloom.core.migrations.url_mask`, which now only re-exports it, and `sandloom.core.cli.url_text` still re-exports `mask_url_credentials` and `mask_query_secrets`. `scrub_text` and the masker used to carry copies of the same patterns. The secret-named query values, and in `scrub_text` the `key=value` pairs too, are now masked before the credentials, so a raw `@` after the name of a secret no longer lets the userinfo run through it: `redis://h:6379/0?password=p@ss` printed `redis://***@ss` and `connect url=postgresql://db:5432/app password=hunter@2` printed `postgresql://***@2`; both now keep the url and print `password=***`.
- **A very long word or a chain of `;x://` pieces in a log line no longer slows the scrubber down** (scrub-dsn-credentials-gaps). The credential pattern rescanned the rest of a letter-and-digit run from every position, so a 32 000 character token in a message with a url in it took seconds per log record; a scheme is now at most 32 characters. The open-password branch chained every `;x://` piece to the end of the line from every start, so 50 000 characters of `y://u:p;` without an `@` took 22 s in the scrubber: the chain is capped at 8 pieces (`sandloom.core.url_mask.MAX_CHAINED_SCHEMES`) and those lines take under 0.1 s. A password that chains more than eight `;x://` pieces has the pieces before its last eight printed.

### Security

- **A url that `urllib` cannot parse no longer carries its password into more kernel errors** (kernel-safe-urlsplit). A netloc character that Unicode-normalizes to `:` `/` `?` `#` or `@` (U+FF1A, say) makes `urlsplit` raise a `ValueError` whose message holds the whole netloc, `user:password` included. The kernel read `DOCKER_HOST` (`sandloom dev`) and the process urls of `contract_testing.split_env` with a bare `urlsplit`, and `split_env` also echoed a well-formed url that is not http(s) with its password; `DOCKER_HOST` now answers a one-line `DockerUnavailable` that names none of its text, and `split_env` reads its urls through `sandloom.core.url_split.split_url` and prints `redact(url)`. The database url of the backup commands and the "database unreachable" warning at startup read through `split_url` too, which replaces the private copy of the backup module. The fixed message of `split_url` now also says how to write the url (plain ASCII host and credentials, closed IPv6 brackets), so the backup commands' message starts with "the url cannot be parsed" instead of "a database url cannot be parsed". A url that was refused is refused now: only the message changes. `TRACING_URL` and `SERVICE_BINDINGS` urls (`sandloom.core.config`) keep their own guard: the configuration layer cannot import `sandloom.core.url_split` (ADR-0007), and neither echoes the url.

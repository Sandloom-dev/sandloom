### Changed

- **A project names the composition its authoring commands build** (idk-test-composition-default). `[tool.sandloom] composition-root` in the project's `pyproject.toml` is now a default for `sandloom generate`, `sandloom admin export`, `sandloom check --boot`, the contract and route snapshots and the static steps of `sandloom test`, behind `SANDLOOM_COMPOSITION_ROOT` (process env, then `.env`) and ahead of `sandloom.main`. The framework checkout names `sandloom_standard.main`, so `uv run sandloom generate` and `uv run sandloom test` work from the repository root with no variable exported. The runtime entrypoints (API, worker), `sandloom migrate` and the pytest suites do not read the key; `sandloom test` sets the variable for its own migration drift step. An application from `sandloom new` is unaffected: it names its root in its `.env` and has no such key. A malformed key (not a table, not a dotted module path, an unreadable file) refuses with `CompositionRootError` instead of falling back to the lean root.

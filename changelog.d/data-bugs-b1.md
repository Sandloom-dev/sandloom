### Fixed

- **`conflict_insert` works on a `TenantScoped` model under a bound tenant** (tenant-upsert-admit). The tenant guard refused every `INSERT` of a `TenantScoped` model that was not an ORM instance, so the documented portable upsert only ran inside `unscoped()`. An `INSERT` with `on_conflict_do_nothing()` or `on_conflict_do_update()` is now admitted when a tenant is bound: a row without `tenant_id` gets the bound tenant, a row naming another tenant raises `UnsafeTenantOperationError`, and `DO UPDATE` gains `tenant_id = <bound tenant>` in its `WHERE`, so a conflict with another tenant's row updates nothing. With no tenant bound it is still refused; `set_` naming `tenant_id`, `from_select`, a subquery and a plain `INSERT` (no `ON CONFLICT`) on a `TenantScoped` model stay refused. Pass the model class, not its `Table` (a Core statement on a tenant table stays refused). Code that wrapped such an upsert in `unscoped()` keeps working; it can drop the wrapper. No upgrade step.
- **`open_uow()` without a name opens the calling module's primary database** (open-uow-module-db). It always opened `default`, while `units.md` promised the module's primary database, so a task or service of a module whose migration chain lives on another database wrote to `default`. The module is the one whose package holds the calling code (`ModuleDescriptor.database_instances()`, the resolution a contract's unit uses); code that no loaded module holds, such as a script, still gets `default`, and so does a module whose `define_module(name=)` differs from its package. A module with several required databases, `default` not among them and no `migrations_database`, has no primary one: `open_uow()` now raises `MigrationTargetError` there (as its contracts already do), so it declares `migrations_database` or passes the name. Upgrade: a module on a non-default database that called `open_uow()` and relied on `default` passes `open_uow("default")`; a module on `default`, the standard modules included, is unchanged.
- **A named bound parameter can no longer write another tenant's row through `conflict_insert`** (review of the tenant upsert). `tenant_id=bindparam("t")` took its value from the execution parameters after the guard had filled the bound tenant in; the guard now reads the parameter from every row (a row value wins over a default, so a parameter with a default was bypassed too), checks the default for rows without the key, and refuses one that is not the bound tenant (or is callable-valued). `set_` may now read the proposed row through `stmt.excluded` (the whole `excluded` row stays refused, as it carries `tenant_id`). No upgrade step.

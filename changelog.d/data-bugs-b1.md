### Fixed

- **`conflict_insert` works on a `TenantScoped` model under a bound tenant** (tenant-upsert-admit). The tenant guard refused every `INSERT` of a `TenantScoped` model that was not an ORM instance, so the documented portable upsert only ran inside `unscoped()`. An `INSERT` with `on_conflict_do_nothing()` or `on_conflict_do_update()` is now admitted when a tenant is bound: a row without `tenant_id` gets the bound tenant, a row naming another tenant raises `UnsafeTenantOperationError`, and `DO UPDATE` gains `tenant_id = <bound tenant>` in its `WHERE`, so a conflict with another tenant's row updates nothing. With no tenant bound it is still refused; `set_` naming `tenant_id`, `from_select`, a subquery and a plain `INSERT` (no `ON CONFLICT`) on a `TenantScoped` model stay refused. Pass the model class, not its `Table` (a Core statement on a tenant table stays refused). Code that wrapped such an upsert in `unscoped()` keeps working; it can drop the wrapper. No upgrade step.

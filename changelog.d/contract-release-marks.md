### Changed

- **Contracts and events are drafts until `sandloom release`** (contract-release-marks). SANDLOOM-T004 and SANDLOOM-T005 refused an incompatible change from the first snapshot on, so a contract or event you had just written could not be reshaped without a new `.vN`. Now an entry is a draft until `sandloom release` marks every contract and exported event of the project released (`released` in `contracts.snapshot.json` and `module.snapshot.json`, `x-sandloom-released` in an exported event file); `sandloom generate` rewrites a draft freely and compares only released entries. A compatible change of a released entry moves its revision, which `sandloom docs <name>` prints. Nothing reads git, a tag or a remote ([ADR-0017](docs/adr/0017-released-marks.md)). Upgrade: snapshots written before the marks count as released at revision 1; run `uv run sandloom generate` once to add the marks and commit the result (`sandloom test` reports the files as stale until then). See "Upgrading to 0.7.0a16" in `docs/operate/upgrade.md`.
- **SANDLOOM-T002 replays the migration chain and SANDLOOM-T012 names the covering unique key** (contract-release-marks). A table a later revision drops, renames or reorders in the chain is judged by the chain's end state, and the redundant-index message names the unique key that already covers the plain index.

### Added

- **`sandloom generate --new-major <name>`** (contract-release-marks). Copies a released contract or event to the next major (`.v1` to `.v2`) beside the old one, renaming the name and the class, then generates. It refuses a draft, an unknown name, a name whose next major exists, and a `--check` run.
- **`sandloom release`** (contract-release-marks). Marks every contract and event the project declares as released and writes the snapshots and exported event files. It is a top-level command because it marks events as well as contracts.
- **`sandloom add contract-use <module> <contract>`** (contract-release-marks). Declares that a module consumes a contract and writes the consumer stub in the same step. In an application the stub is written before the consumer's first use, and `sandloom docs <contract>` prints the application's own `<app>.shared.contracts` import path.

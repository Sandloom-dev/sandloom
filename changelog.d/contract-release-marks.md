### Changed

- **Contracts and events are drafts until `sandloom release`** (contract-release-marks). SANDLOOM-T004 and SANDLOOM-T005 refused an incompatible change from the first snapshot on, so a contract or event you had just written could not be reshaped without a new `.vN`. Now `sandloom release` marks every contract and exported event of the project released (`released` in `contracts.snapshot.json` and `module.snapshot.json`, `x-sandloom-released` in an exported event file); `sandloom generate` rewrites a draft freely and compares only released entries. A draft is explicit, never inferred from absence: it is what `sandloom new` (the sample) and `sandloom add module|contract|event|saga|projection` create, a new entry in a snapshot file that exists, or a name passed to `sandloom generate --draft`. A snapshot file that does not exist is written with every current entry released, so deleting or renaming one never unprotects a release. A change of a released entry moves its revision, which `sandloom docs <name>` prints. Nothing reads git, a tag or a remote ([ADR-0017](docs/adr/0017-released-marks.md)). Upgrade: snapshots written before the marks count as released at revision 1; run `uv run sandloom generate` once to add the marks and commit the result (`sandloom test` reports the files as stale until then). See "Upgrading to 0.7.0a16" in `docs/operate/upgrade.md`.
- **An installed module package's events always count as published** (contract-release-marks). The application compares the exported copy of each of them with the package's schema on every generate (T005) whatever the package marks, and a package mark that is not a revision is reported.
- **SANDLOOM-T002 replays the migration chain and SANDLOOM-T012 names the covering unique key** (contract-release-marks). A table a later revision drops or renames is judged by the chain's end state (a drop or rename that is unconditional in `upgrade()`; revisions run in `down_revision` order, merges in the list form too), while a table created by two chains is reported whichever chain later drops it. The redundant-index message names the unique key that already covers the plain index.

### Added

- **`sandloom generate --new-major <name>`** (contract-release-marks). Copies a released contract or event to the next major (`.v1` to `.v2`) beside the old one, renaming the name and the class, then generates. Restore the released declaration first, then run it, then edit the copy; a contract copy reuses the old major's DTO classes. It refuses a draft, an unknown name, a name whose next major exists, and a `--check` run, and finds the module of a tree of top-level packages (`src/sandloom_<name>`).
- **`sandloom generate --draft <name>`** (contract-release-marks). Writes the named contract, event, or all of a module's entries as drafts. It refuses a name that is released, a name that is none of them, and a `--check` run.
- **`sandloom release`** (contract-release-marks). Marks every contract and event the project declares as released and writes the snapshots and exported event files. It is a top-level command because it marks events as well as contracts.
- **`sandloom add contract-use <module> <contract>`** (contract-release-marks). Declares that a module consumes a contract and writes the consumer stub in the same step. In an application the stub is written before the consumer's first use, and `sandloom docs <contract>` prints the application's own `<app>.shared.contracts` import path. When two modules import each other's stubs before either exists, the refusal says that they wait on each other.

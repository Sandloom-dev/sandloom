### Breaking changes

- **`sandloom check` refuses a `public_api` that lists the kernel** (public-api-drop-core). A business module imports `sandloom.sdk` and nothing of `sandloom.core`, and the manifest now says so: `load_rules` raises SANDLOOM-C038 for a `public_api` entry that is `sandloom.core`, a `sandloom.core.*` module or the bare `sandloom` (the import check matches an entry by prefix, so each would still let a module import the kernel), and `sandloom check` exits with 2 before it scans any module. There is no warning phase. The message names the entries to delete and points at `docs/operate/upgrade.md`. `DEFAULT_PUBLIC_API`, the list a manifest without `public_api` gets, is the `sandloom.sdk` modules; the repository's `architecture_rules.yml`, the six examples and the `sandloom new` scaffold list no `sandloom.core` module (the scaffold's README no longer calls `sandloom.core.*` the allowed API), and `public_api_baseline.json` no longer records `sandloom.core.di`, `facade`, `module_api`, `descriptors`, `orm` and `projections`. Upgrade: delete every `sandloom.core.*` line from `public_api` in your `architecture_rules.yml` (an application scaffolded before this release lists six), run `uv run sandloom check`, and move each import it then reports to its `sandloom.sdk` home ([Public API 1.0](docs/operate/upgrade-1.0.md)). A module's tests keep `sandloom.core.testing` and `sandloom.core.contract_testing` through `test_api`.

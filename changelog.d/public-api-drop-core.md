### Breaking changes

- **A `public_api` that lists the kernel is refused by every command that reads the manifest** (public-api-drop-core). A business module imports `sandloom.sdk` and nothing of `sandloom.core`, and the manifest now says so: `load_rules` raises SANDLOOM-C038 for a `public_api` entry that is `sandloom.core`, a `sandloom.core.*` module or the bare `sandloom` (the import check matches an entry by prefix, so each would still let a module import the kernel). `sandloom check` exits with 2 before it scans any module, and `generate`, `test`, `add` and `add deploy` stop with the same code. There is no warning phase. The private layers of the sdk (`sandloom.sdk._*`, `sandloom.sdk.*._*`) are forbidden imports whatever the manifest says, so the sdk default of `public_api` does not admit them by prefix. The C038 check reads `public_api` only, not `allowlist`, `framework_packages` or `kernel_package`. The message names the entries to delete and points at `docs/operate/upgrade.md`. `DEFAULT_PUBLIC_API`, the list a manifest without `public_api` gets, is the `sandloom.sdk` modules; the repository's `architecture_rules.yml`, the six examples and the `sandloom new` scaffold list no `sandloom.core` module (the scaffold's README no longer calls `sandloom.core.*` the allowed API), and `public_api_baseline.json` no longer records `sandloom.core.di`, `facade`, `module_api`, `descriptors`, `orm` and `projections`. Upgrade: delete every `sandloom.core.*` line from `public_api` in your `architecture_rules.yml` (an application scaffolded before this release lists six), run `uv run sandloom check`, and move each import it then reports to its `sandloom.sdk` home ([Public API 1.0](docs/operate/upgrade-1.0.md)). A module's tests keep `sandloom.core.testing` and `sandloom.core.contract_testing` through `test_api`.

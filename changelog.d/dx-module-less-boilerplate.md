### Added

- **`NotFound`, `Conflict` and `Refused(status, detail)` in `sandloom.sdk`** (dx-module-less-boilerplate). A module raises its own refusal without importing FastAPI: `raise NotFound("No profile yet")`. They are `HTTPException` subclasses, so a route, a contract call and a saga step handle them as before: the response body is `{"detail", "code"}` with the code `not_found` or `conflict`, a contract caller gets the same refusal, and a saga step classifies them like the `HTTPException` it raised before (`404` is refused, `409` is retried). `Refused` takes a status from 400 to 499 and raises `TypeError` or `ValueError` for anything else. The name `NotFound` also exists in `sandloom.sdk.infra` (an infrastructure error): import the one you mean.
- **`Versioned`, a mixin for a model that feeds a projection** (dx-module-less-boilerplate). It adds `version: BigInteger` (default 1) and increments it in the same `UPDATE` statement, so a service stops bumping the version by hand. It is in `sandloom.sdk.data` (advanced tier).
- **`db()` works where a session parameter remained** (dx-module-less-boilerplate). The `authorize_resource` loader (`async def load(resource_id)`), a saga `local_step` apply (`async def apply(ctx)`), a projection handler (`async def apply(envelope)`) and `monotonic_upsert` / `monotonic_update` / `monotonic_delete` (`monotonic_upsert(Row, key=..., ...)`) read the unit's session from `db()`. The form with a session stays and is not deprecated: it emits no warning and is documented as the legacy form.
- **`sandloom check` reports T009** (dx-module-less-boilerplate). An advanced `sandloom.sdk` import without `# sandloom: advanced <reason>` was a gate of `sandloom test` only; `sandloom check` now lists it with the other rules, on a full run (not with `--only`).

### Changed

- **A model gets its server defaults and its id without a flush** (dx-module-less-boilerplate). `Base` sets `eager_defaults=True`, so `created_at`, `updated_at` and `version` are readable after `flush()` without a refresh round trip, and a primary key declared with `default=new_id` is assigned at construction (`Ticket(...).id` is set before the row is added). An explicit `id=` still wins. A model that declares its own `__mapper_args__` (single-table polymorphism) names `eager_defaults` itself.
- **The beginner tier is 42 names** (dx-module-less-boilerplate). The root `sandloom.sdk` gains `NotFound`, `Conflict`, `Refused`, `UpdatedAt` and `bind_tenant` (25 names). `sandloom.sdk.sagas` has 5 beginner names (`Saga`, `SagaContext`, `local_step`, `start_saga`, `step`) and `sandloom.sdk.projections` 6 (`Projection`, `ProjectionView`, `SourceGroup`, `View`, `full_state`, `tombstone`). A module importing them needs no `# sandloom: advanced` comment, and `sandloom check` and `sandloom test` agree on that list.
- **`SANDLOOM-C009`, `SANDLOOM-C010` and `SANDLOOM-T009` say what to do** (dx-module-less-boilerplate). `sandloom explain` names the fix of each in the current form (`db()`, `Versioned`, the beginner tier).
- **The examples and the module guide teach the short form** (dx-module-less-boilerplate). The five examples use `NotFound` / `Conflict` / `Refused`, `db()` in a loader and a saga step, and `Versioned`; the module contract (`module-AGENTS.md`), the API cheat sheet and the docs pages say the same.

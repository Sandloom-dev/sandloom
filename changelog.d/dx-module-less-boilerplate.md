### Breaking changes

- **The session-parameter forms are removed: `db()` is the one spelling** (dx-module-less-boilerplate). Five forms took the session as a parameter and are gone, with no deprecated second form and no detection by argument count. Each fails with a `TypeError` that names the rewrite: the first three where the function is declared, the last two at the call that passes a session first:
  - `local_step("s", apply=fn)` with `async def fn(session, ctx)` (also `compensate=`): `TypeError: local_step(apply=...) takes async def f(ctx) and writes through db(); ...`, when the saga module is imported. Write `async def fn(ctx)` and read and write through `db()`.
  - `authorize_resource(loader=load, ...)` with `async def load(id, session)`: `TypeError: authorize_resource(loader=...) takes async def load(id) ...`, when the route's dependency is built. Write `async def load(id)` and read through `db()`.
  - A projection consumer handler `async def h(session, envelope)`: `TypeError: consumer '<name>': handler takes async def f(envelope) ...`, when the descriptor is built. Write `async def h(envelope)` and write through `db()`.
  - `monotonic_upsert(session, Row, key=..., ...)`, `monotonic_update` and `monotonic_delete`: `TypeError: monotonic_upsert(session, ...) is gone: it writes through db() ...` when the first argument is a `Session` or `AsyncSession` (any other extra argument keeps Python's own `TypeError`). Write `monotonic_upsert(Row, key=..., ...)`: the keywords are unchanged and a keyword call (`target=Row`) works.
  - `await projection.apply(session, group, event, mapper)`: `TypeError: projection.apply(session, group, event, mapper) is gone: it writes through db() ...` when a `Session` or `AsyncSession` comes right after the projection. Write `await projection.apply(group, event, mapper)` inside a unit.
  The kernel runtimes keep `(session, ...)` internally behind adapters, and a raw L2 consumer registered with `register_event_consumer` keeps `async def handler(session, envelope)`. The [upgrade guide](docs/operate/upgrade-1.0.md#session-parameters-leave-the-author-surface) has the table.
- **`Owner` and `authorize_resource` leave the root `sandloom.sdk`; `Account` joins it** (dx-module-less-boilerplate). `from sandloom.sdk import Owner` is an `ImportError`: write `from sandloom.sdk.authz import Owner, authorize_resource  # sandloom: advanced <reason>`. `from sandloom.sdk import Account` replaces `from sandloom.sdk.authz import Account  # sandloom: advanced ...`. `fake_access_fact` is advanced too: its import needs the marker.

### Added

- **`NotFound`, `Conflict` and `Refused(status, detail)` in `sandloom.sdk`** (dx-module-less-boilerplate). A module raises its own refusal without importing FastAPI: `raise NotFound("No profile yet")`. They are `HTTPException` subclasses, so a route, a contract call and a saga step handle them as before: the response body is `{"detail", "code"}` with the code `not_found` or `conflict`, a contract caller gets the same refusal, and a saga step classifies them like the `HTTPException` it raised before. `Refused` takes a status from 400 to 499 and raises `TypeError` or `ValueError` for anything else; without a detail it answers the status phrase (`Client Error` for a status such as 499 that has none). A saga local step refuses for good on 400, 402, 403, 404, 410 and 422, parks the saga as misconfigured on 401, and retries any other status (`Conflict` 409 included). The name `NotFound` also exists in `sandloom.sdk.infra` (an infrastructure error, such as an object store's missing key). It is an unrelated class: `except NotFound` with `sandloom.sdk.NotFound` does not catch a storage miss, which stays a 500 until you catch `sandloom.sdk.infra.NotFound` and raise yours.
- **`Versioned`, a mixin for a model that feeds a projection** (dx-module-less-boilerplate). It adds `version: BigInteger` (default 1) and increments it in the same `UPDATE` statement, so a service stops bumping the version by hand. It also checks the update: the ORM writes `WHERE version = <the version the unit loaded>`, and a row another transaction updated in between makes the flush raise `sqlalchemy.orm.exc.StaleDataError` and write nothing, so no event carries a newer version with columns the unit never read. A joined-table child that changes only its own columns counts up too. Read the row with `select(...).with_for_update()` to wait for the other transaction instead. A `Versioned` model whose own `__mapper_args__` drops the check is refused when it is declared. It is in `sandloom.sdk.data` (advanced tier).
- **`db()` works where a session parameter remained** (dx-module-less-boilerplate). The `authorize_resource` loader (`async def load(resource_id)`), a saga `local_step` apply (`async def apply(ctx)`), a projection handler (`async def apply(envelope)`) and `monotonic_upsert` / `monotonic_update` / `monotonic_delete` (`monotonic_upsert(Row, key=..., ...)`) read the unit's session from `db()`. A function with a defaulted second parameter (`async def load(resource_id, include_archived=False)`) takes the id alone: the second parameter is never handed the session.
- **`sandloom check` reports T009** (dx-module-less-boilerplate). An advanced `sandloom.sdk` import without `# sandloom: advanced <reason>` was a gate of `sandloom test` only; `sandloom check` now lists it with the other rules, on a full run (not with `--only`), and reads the manifest `--rules` names.

### Changed

- **A model gets its server defaults and its id without a flush** (dx-module-less-boilerplate). `Base` sets `eager_defaults=True`, so `created_at`, `updated_at` and `version` are readable after `flush()` without a refresh round trip, and a primary key declared with `default=new_id` is assigned at construction (`Ticket(...).id` is set before the row is added). An explicit `id=` still wins. A model that declares its own `__mapper_args__` (polymorphic inheritance) keeps `eager_defaults`: a listener on `Base` turns SQLAlchemy's unset value into `True`, and a model that names `eager_defaults=False` keeps its choice. Constructing a model configures only the mappers of its own registry.
- **The beginner tier is 29 names, with a second tier of 12** (dx-module-less-boilerplate). Tier 1 is the 24 names of `sandloom.sdk` (the earlier 20 less `Owner` and `authorize_resource`, plus `Account`, `NotFound`, `Conflict`, `Refused`, `UpdatedAt` and `bind_tenant`) and five test helpers (`client`, `as_user`, `published`, `deliver`, `fake_contract`): free in any file. Tier 2 is `Saga`, `SagaContext`, `step`, `local_step`, `start_saga` (`sandloom.sdk.sagas`), `Projection`, `SourceGroup`, `full_state`, `tombstone` (`sandloom.sdk.projections`), `task`, `periodic` (`sandloom.sdk.tasks`) and `open_uow` (`sandloom.sdk.data`): free in the module file `sandloom add` writes them into (`sagas.py`, `projections.py`, `tasks.py`), and a `# sandloom: advanced <reason>` comment in any other file. `View`, `ProjectionView` and `unscoped` stay advanced. A name's place follows a measured criterion, recorded in ADR-0010 (the second amendment). `sandloom check` and `sandloom test` agree on the list.
- **`SANDLOOM-C009`, `SANDLOOM-C010` and `SANDLOOM-T009` say what to do** (dx-module-less-boilerplate). `sandloom explain` names the fix of each in the current form (`db()`, `Versioned`, the two tiers).
- **The examples and the module guide teach the short form** (dx-module-less-boilerplate). The five examples use `NotFound` / `Conflict` / `Refused`, `db()` in a loader, a saga step and a projection handler, and `Versioned`; the module contract (`module-AGENTS.md`), the API cheat sheet and the docs pages say the same.

### Fixed

- **The inspection index names the author's function of a saga step** (dx-module-less-boilerplate). `.sandloom/inspection.json` (written by `sandloom generate`) followed the framework's adapter and recorded no source for a `local_step`; it unwraps to the function the author wrote.

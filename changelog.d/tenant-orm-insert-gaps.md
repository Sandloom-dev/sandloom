### Breaking changes

- **A `TenantScoped` model is refused when it is defined if its plain insert would reach another tenant through the database** (tenant-orm-insert-gaps).
  The cursor guard sees the values and the filters of a statement, not what the database does with an insert whose every value is the bound tenant's. Three declarations let it reach another tenant's row, and each raises `UnsafeTenantModelError` (an `UnsafeTenantOperationError`) with its own code before any table or row exists.
  `SANDLOOM-R019`: a `REPLACE` conflict clause (SQLite's `sqlite_on_conflict="REPLACE"` on a primary key, a unique constraint or a column) deletes the row that holds the key, whichever tenant owns it. `SANDLOOM-R020`: a foreign key from a tenant table to another tenant table that does not pair `tenant_id` on both sides lets the insert lock and probe a parent row of another tenant, which PostgreSQL does outside row-level security; the error names the composite key to use. The table of a joined subclass is a tenant table without a tenant column: no key on it or to it can pair one, so only its inherit key (its primary key to the table it inherits from) is exempt, a key of the subclass is declared on the base table, and a key to the subclass targets the base table. `SANDLOOM-R021`: the attribute `tenant_id` must be a mapped column over exactly one plain `Column` of the model's own tables, with the default comparator, and of exactly SQLAlchemy's `Uuid`. A `synonym`, a `hybrid_property`, an expression, a comparator of its own, a subclass that leaves the column out, a second column called `tenant_id` that the attribute does not map, and a `TypeDecorator`, a `UserDefinedType`, a subclass or a `type_coerce` of the column are refused: the guard, R020 and R021 would read a column other than the one a statement binds, and `tenant_upsert` relied on the type.
  The check reads every table the mapper of a `TenantScoped` class maps, however it was declared (`__table_args__` or a column keyword, `mapped_column` or `Column`, a mixin, inheritance, imperative mapping, one `Table` under two models), and refuses a constraint or a column attached to such a table afterwards. It runs once when the model is defined and costs the keys of the new model plus the keys that point at it; no statement pays for it.
  **Upgrade:** a foreign key to another tenant table becomes composite, `ForeignKeyConstraint(["tenant_id", "parent_id"], ["parent.tenant_id", "parent.id"])`, over a `UniqueConstraint("tenant_id", "id")` on the parent, with a migration for an existing table. A joined subclass moves its foreign keys to the base table, and a key to a subclass targets the base table. A model with `sqlite_on_conflict="REPLACE"` drops it or uses a composite key. A model that maps `tenant_id` through a synonym, a hybrid or an expression maps the column itself. A tenant column of another type becomes `Uuid`, and the conversion moves to a column that is not the tenant. A foreign key to a table without `tenant_id`, and one declared on a table that is not `TenantScoped`, are not read.
  Docs: [Multi-tenancy](docs/modules/database/multi-tenancy.md#what-the-database-does-with-a-plain-insert), [ADR-0018, decision 7](docs/adr/0018-tenant-guard-at-the-cursor.md) (G-TENANT-28).

### Changed

- **`tenant_upsert` reads the options a model declares and says so** (tenant-orm-insert-gaps).
  The helper refuses a model that declares a `<dialect>_on_conflict*` option of any value on a column, a constraint or an index (`SANDLOOM-R018`), as before. The declared options are read, never the live database schema, so a table built by hand or by a migration with a clause the model leaves out is not read; R018, G-TENANT-27 and the docs now say so. The docstring also states that a driver that batches the parameter sets into one statement (psycopg2) hands PostgreSQL a repeated key twice in one `ON CONFLICT DO UPDATE`, which it refuses, and that PostgreSQL runs a uniqueness check outside row-level security, so a policy does not hide it.

### Breaking changes

- **The volatile event bus driver is `broadcast`, not `redis`** (eventbus-broadcast-driver). The `eventbus` driver that runs over a `broadcast` instance talks to no service of its own, so it is named after the capability it runs on. `INFRA={"eventbus": {"default": {"driver": "broadcast"}}}` replaces `"driver": "redis"`, and `EVENT_BUS_BACKEND=broadcast` replaces `redis`. The driver no longer declares the `redis` package as a requirement and imports nothing of Redis. The old name has no alias: startup refuses an `eventbus` instance that writes `redis`, whether it comes from `INFRA`, a composition's `DEFAULT_INFRA`, a configuration built in code or `EVENT_BUS_BACKEND`. The error names the new spelling and prints no option. The `redis` driver of `cache`, `lease`, `atomic_store` and `broadcast` is unchanged. The kernel classes `RedisEventBus` and `RedisEventBusProvider` are renamed `BroadcastEventBus` and `BroadcastEventBusProvider`; neither is exported from `sandloom.core.eventing`. See [Upgrading to 0.7.0a15](https://sandloom.dev/docs/operate/upgrade/#upgrading-to-070a15-the-volatile-event-bus-driver-is-broadcast).

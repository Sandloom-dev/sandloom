# Changelog — sandloom-celery

## [Unreleased]

## [0.7.0a15] — 2026-11-18

### Breaking changes

- **A `rediss://` url must state how it verifies the server** (idk-celery-conf-audit). Kombu connected such a broker with no certificate check and only logged a warning, while Celery's result backend already refused the same url. The `celery` taskqueue options now refuse a `rediss://` `broker` or `backend` without `ssl_cert_reqs`, and one that verifies the certificate without `ssl_check_hostname=true` (redis-py before 6 accepts any name of a trusted CA otherwise), naming the option. Upgrade: add `?ssl_cert_reqs=required&ssl_check_hostname=true` to the url, or `?ssl_cert_reqs=none` to state that the check is skipped.
- **An `sqs://` url with a host now uses HTTPS** (idk-celery-conf-audit). Kombu built `http://<host>` for it unless `is_secure` was set. The driver states `is_secure` in the transport options, and a config module may repeat it but not turn it off, so a plain-HTTP emulator is no longer reachable. A `predefined_queues` entry of a config module may carry only its queue `url` (an AWS https queue url, on the public, FIPS or VPC endpoint host) and the backoff keys: its own credentials, region and endpoint are refused. The queue `url` and the `region` option must name the region of the `INFRA` url's AWS host (else the conf `region`), and the queue `url` the account of the `sqs_account_id` option when it is set.
- **A padded or empty `;` chunk of a broker or backend url is refused** (idk-celery-conf-audit). Kombu split a failover url on `;` without stripping, so a chunk such as ` redis://other:6379` slipped past the scheme check.
- **More result-backend keys are refused in a config module** (idk-celery-conf-audit). `dynamodb_endpoint_url`, `firestore_project`, `s3_base_path`, `gcs_base_path` and `azureblockblob_base_path` are refused. The Azure container and the Cosmos DB database and collection names are accepted only at their Celery defaults. State the endpoint in the `backend` url.
- **An `sqs://` broker url with a host the driver cannot read a region from is refused** (idk-low8-celery). The queue-url pin reads the region out of the `INFRA` host, so a host with a trailing dot (`sqs.eu-west-1.amazonaws.com.`), a percent escape or a non-ASCII character (kombu decodes `%2E` or U+3002 into a real AWS host), the legacy `<region>.queue.amazonaws.com`, the dual-stack `sqs.<region>.api.aws` and `sqs-fips.<region>.amazonaws.com.cn` (the China regions have no FIPS endpoint) left the pin silently off. The `celery` taskqueue options now refuse each at startup, naming the option and no url. Upgrade: use `sqs.<region>.amazonaws.com`, the `sqs-fips.<region>.amazonaws.com` name (outside China) or a `vpce-<id>.sqs.<region>.vpce.amazonaws.com` interface endpoint. An emulator or proxy host without a trailing dot is still accepted. A queue `url` of a config module on `sqs-fips.<region>.amazonaws.com.cn` is refused too. The AWS hosts of one `sqs://` url must name one region: a url with hosts of two regions is refused.

### Security

- **A named Celery instance no longer becomes `celery.current_app`** (idk-celery-conf-audit). Building `INFRA.taskqueue.aux` made its app the thread's current app, so a later unbound `@shared_task` `.delay()` published to the `aux` broker. Only the `default` instance, when it is the process-wide app, is made current. A worker process still takes the one app it runs as current, which is Celery's own rule and a known gap of the audit.
- **The conf check covers the rest of the result-backend connection keys and the SQS and sentinel transport options** (idk-celery-conf-audit). `database_url`, the MongoDB, Couchbase, ArangoDB, Cassandra, S3, GCS and cache backend settings, `sentinel_kwargs`, and the SQS `is_secure`, `port` and `sts_role_arn` are refused in a config module, like the keys the check already refused. `database_engine_options` and `broker_failover_strategy` are accepted only in a shape that cannot name another host. An `amqps://` broker verifies the certificate chain and not the hostname, which the driver cannot change.
- **A broker or backend url that `urllib` cannot parse no longer carries its password into the error** (idk-low9). A netloc character that Unicode-normalizes to `:` `/` `?` `#` or `@` (U+FF1A, say) makes `urlsplit` raise a `ValueError` whose message holds the whole netloc, `user:password` included, and the validation error of the instance's options copied it. `connection_policy.scheme_of`, the SQS host reads and the TLS check now raise one fixed message that names no part of the url; the original exception is not chained. Such a url was refused before and is refused now: only the message changes.

### Added

- **`master_name` and `backend_master_name` options for a `sentinel://` url** (idk-celery-conf-audit). Kombu and Celery read the master only from the transport options, which the conf check refuses for a connection key, so a `sentinel://` broker could not connect. The master is now an `INFRA.taskqueue.<name>` option and a `sentinel://` url without it is refused. A config module may repeat the same master.
- **`sqs_account_id` option for an `sqs://` broker** (idk-celery-conf-audit). The 12-digit AWS account of the broker's queues: a `predefined_queues` url of a config module in another account is refused, so a config module copied from another environment cannot publish there. Optional, and refused with any other scheme.
- **The Celery task queue implements `backup_hint`** (redis-out-runtime). A broker on a `redis://` or `rediss://` url reports its AOF advice and the note that a lost broker loses queued tasks, as the kernel did before. Other brokers report nothing.

### Changed

- **The transport options a config module may carry depend on the scheme** (idk-celery-conf-audit). The SQS `region` and `queue_name_prefix`, the redis `retry_on_timeout`, `ack_emulation` and `unacked_*` keys, the amqp read and write timeouts, `broker_login_method` (a SASL mechanism, no route) and the result backend's `result_chord_ordered` are accepted. `design/infra-drivers/celery-conf-audit.md` lists every key with its decision.
- **The Celery task queue isolates `broker` and `backend` through `isolated_url_options`** (redis-out-harness). It replaces `isolated_redis_options`, which the kernel no longer exports, so the package needs the kernel that has `sandloom.driverkit.testing_isolation.isolated_url_options`. Upgrade the package with the kernel. Behaviour is the same: a worker's broker and backend urls move to its own database index when the Redis harness family is installed.
- **The task queue's `isolation_identity` reads the broker through `split_url`** (redis-out-harness). A `broker` url that `urlsplit` cannot read raises a `ValueError` with a fixed message, not one that quotes the netloc and its password. The connection policy (`connection_policy.py`) has the same gap and is fixed by PR #317, not here.

## [0.7.0a14] — 2026-11-16

### Breaking changes

- **The `celery` task queue driver fills only `health_timeout_seconds` from a setting** (idk-flat-urls-z). `BROKER_URL` and `CACHE_URL` are removed settings: the broker is the `broker` option of the `taskqueue` instance and the result backend is the `backend` option, off unless stated. The driver's `settings_fill` keeps the readiness probe's bound (`HEALTH_CHECK_TIMEOUT_SECONDS` into `health_timeout_seconds`, as cap and bound). Upgrade: [Upgrading to 0.7.0a14](https://sandloom.dev/docs/operate/upgrade/#upgrading-to-070a14-the-flat-redis-settings).

### Security

- **The app a `taskqueue` provider publishes through refuses a `CELERY_*` broker or backend that differs from `INFRA`** (idk-flat-urls-z). Celery's `app.conf` prefers `CELERY_BROKER_URL`, `CELERY_BROKER_READ_URL`, `CELERY_BROKER_WRITE_URL` and `CELERY_RESULT_BACKEND` (and a config module) over the url the app was built with, so a stray one silently redirected every publish. On the provider's first use its final `app.conf` is compared with the instance's `broker` and `backend` and a difference raises `ForeignCeleryConfError`, not an outage (nothing was sent), naming the option and the instance, never a url. A value equal to `INFRA`, or blank, passes. The importable app already did this. The check also refuses any `broker_transport`, `broker_host`, `broker_port`, `broker_vhost`, `broker_user` or `broker_password` in the conf (`broker_transport = "memory"` sank every publish into an in-process queue; the others filled in what the `INFRA` url omitted), and it runs on every use of the app, not only the first, so a `CELERY_BROKER_URL` set later is refused too. It also refuses a `broker_use_ssl` that is anything but absent, `None` or `False` (kombu merges a dict there into the connection after the url: `host`, `port`, `password` and `virtual_host` redirected it, `ssl_cert_reqs: CERT_NONE` turned certificate verification off for a `rediss://` url; `True` made a `rediss://` connection fall back to plain text and send the password in the clear; TLS comes from the scheme and the url's query) and a `redis_host`, `redis_port`, `redis_db`, `redis_username`, `redis_password`, `redis_backend_use_ssl` or `redis_backend_credential_provider`, which the redis result backend takes where its url omits the part. `broker_transport_options` and `result_backend_transport_options` accept only an allow-list of tuning keys (timeouts, keep-alive, pool size, key prefix, retry and visibility options, listed in `docs/modules/background/tasks.md`): an `amqp://` broker takes its host, user, password and `ssl` from them, and a `sentinel://` broker its master, so any other key is refused, named by its option only. Every broker scheme stays supported.

### Added

- **A startup warning when the broker is the cache's Redis database** (idk-flat-urls-no-follows). `CeleryTaskQueueProvider.aopen` registers the broker's `host:port/db` in `sandloom.driverkit.shared_endpoints` and logs one WARNING when it is the endpoint of `cache.default`: a cache that evicts can drop queued tasks. The log names both instances and never carries the broker's password; nothing is refused, and the package imports no other driver package. A queue the kernel synthesized is logged at INFO. `aclose` unregisters the queue.

### Changed

- Add the Celery driver `taskqueue.celery` and its worker and scheduler host as an optional package. They left the kernel wheel; `sandloom[celery]` installs this package.
- **`celery -A sandloom_celery.worker` reads its broker from `INFRA`, not from the `BROKER_URL` variable** (idk-flat-urls-c). The importable app (`app`, `celery`, `celery_app`; for `celery inspect`, `call`, `status` and Flower) is built, on first use and with no import side effect, from the options of the `default` task queue as the application resolves them: `Settings` (environment and `.env`), the composition's selection, `INFRA` over it. State the broker as `INFRA='{"taskqueue":{"default":{"broker":"redis://..."}}}'`. Without one the lookup raises `AttributeError` naming `taskqueue.default.broker`, and a `default` task queue that is not the `celery` driver is refused with a message saying so. The module no longer reads `os.environ["BROKER_URL"]` (`BROKER_URL_ENV` is removed). A stray `BROKER_URL` in the environment still cannot replace the broker of a worker or a beat: `sandloom worker` and `sandloom beat` keep hiding Celery's own `BROKER_URL` option variable for the run. The importable app is stricter than before about the same variables: Celery's CLI writes `CELERY_BROKER_URL` from `-b` / `BROKER_URL` and `CELERY_RESULT_BACKEND` from `--result-backend` / `RESULT_BACKEND`, and `app.conf` prefers them over the app's own broker, so the app raises `AttributeError` naming the variable (never its value) when `CELERY_BROKER_URL`, `CELERY_BROKER_READ_URL`, `CELERY_BROKER_WRITE_URL` or `CELERY_RESULT_BACKEND` is set to something other than what `INFRA` states. A value equal to `INFRA`'s, or a blank one, passes. The app also compares its finished `app.conf` (`broker_url`, `broker_read_url`, `broker_write_url`, `result_backend`) with `INFRA` and raises `AttributeError` naming the option when one differs, because a config module (`celery --config X`, `CELERY_CONFIG_MODULE`) or the default loader (`--loader default` imports `celeryconfig.py` from the working directory) can set a write broker or a result backend that the environment check does not see; the check also runs when the provider built the process-wide app first, and `celery -A sandloom_celery.worker` gets no app out of a refusal: the module keeps the process-wide app in a holder, not in a module-level name, because Celery's `-A` lookup falls back to any `Celery` instance in the module once `app` and `celery` raise. Upgrade: a service that ran `celery -A sandloom_celery.worker ...` with only `BROKER_URL` set (and no `INFRA`) puts the broker into `INFRA` as above; the kernel refuses `BROKER_URL` at startup.
- **`backend` has no default and is documented as optional** (idk-flat-urls-c). Sandloom never reads a task result (`task_ignore_result` is on), so an instance that states no `backend` runs with no result backend. The kernel fills nothing: leave `backend` out of `INFRA` unless you read results. The importable app now takes the same `backend` as the provider's `default` instance (before: always none).
- **The importable app needs the kernel's configuration to be valid.** Reading `INFRA` loads `Settings`, so an invalid configuration (for example a missing `DATABASE_URL`) stops `celery -A sandloom_celery.worker` with the configuration error, where it used to start from `BROKER_URL` alone.
- **A `celery` task-queue instance with no broker is refused at startup, and the message names the INFRA option** (idk-flat-urls-s0a). The build raises `MissingBrokerError` (a `ValueError`, `fatal_at_startup`) saying `celery taskqueue instance 'default' has no 'broker' option: set the INFRA option taskqueue.default.broker, e.g. INFRA='{...}'`.
- **An app the conf check refuses never becomes `celery.current_app`** (idk-low5-product). The driver built its apps with `Celery(...)`, which makes the new app current at construction, so an app refused for a foreign broker or result backend stayed the process's current app. It now builds with `set_as_current=False` and calls `app.set_current()` once the check has passed, for the provider's app and for the importable one.
- **`redis>=5.2.1,<6` is a dependency of its own, and `hiredis` is an optional extra** (idk-low5-product). `celery[redis]` accepted any redis release; the bound is the one `sandloom-redis` has. `pip install sandloom-celery[hiredis]` adds the hiredis parser.

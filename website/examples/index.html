Example applications

Find your starting point.

Four standalone applications, each focused on a different Sandloom pattern. Explore how the public SDK fits real business code, from one module to a process spanning several.

New to Sandloom? Follow the first-feature tutorial →

01 / Minimal application

Linkly

A URL shortener with public routes, a cache-backed lookup and a typed link-created event. A compact starting point without bundled identity or billing.

  • One business module
  • Public route policy
  • Cache and typed events

Source in the repository examples/linkly/

Understand route policies →

02 / SaaS with bundled modules

Helpdesk

Organization ticketing that builds on identity, tenancy and billing. Membership checks use a contract; organization billing gates protect access.

  • Organizations and roles
  • Contracts and billing gates
  • Events and audit records

Source in the repository examples/helpdesk/

Understand authorization →

03 / Cross-module process

Academy

A course-enrollment flow across enrollment, payments and notifications. A saga coordinates the steps, compensation and retries.

  • Three isolated modules
  • Typed saga steps and commands
  • Compensation and retry boundaries

Source in the repository examples/academy/

Understand sagas →

04 / Cross-module read model

Projecthub

A taskboard built from projects and tasks events. A projection maintains a read model for queries across module boundaries.

  • Typed event views
  • Durable projection consumers
  • Cross-module queries without runtime joins

Source in the repository examples/projecthub/

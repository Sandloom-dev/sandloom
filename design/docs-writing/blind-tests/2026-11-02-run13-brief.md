## Purpose

*Operator, from the owner's recorded decisions:* "The reader wants to try Sandloom: with an agent they paste the prompt, without one they open the quickstart. Architecture, concepts and Reference stay on their own pages."

- **Effect.** The reader understands what Sandloom gives their backend and why, and starts: pastes the prompt into their agent, or opens the quickstart.
- **Place.** Readers arrive from the site's home, GitHub, a search or a link someone shared, and from an agent fetching `llms.txt`. Next: the agent tab's prompt, or the quickstart; readers who want more before trying go to How Sandloom works, the examples, the ready-made parts or Reference.
- **Sign it worked.** A reader who never saw Sandloom says "it keeps the parts of my backend separate and checks it, so the agent can't tangle it", and either pastes the prompt or runs the first quickstart command.
- **Not its job.** Architecture and principles (`architecture.md`), concepts (`modules/index.md` and below), the install steps (`getting-started/index.md`), lookup (`reference/index.md`).

## One message

From the positioning, used as the bold first sentence: **Sandloom is a Python backend framework designed for AI-driven development.**

## Promise

*Operator, from the owner's recorded decisions:* outcomes, not features. The backend:

1. stays quick to change as it grows;
2. runs reliably;
3. splits from one application into services without a rewrite.

Matches the positioning's Value (speed, reliability, scalability, split without rewriting), with scalability and the split merged as the closest pair.

## Core idea

Positioning, raw meaning: "Sandloom keeps your business logic atomic and isolated from each other and from the infrastructure."

*Operator, from the owner's recorded decisions:* in a natural sentence: the business logic is atomic, isolated from the other parts of the product and from the infrastructure. The page writes it as a natural sentence, not word for word, and avoids "infrastructure" bare: "the database and the other services it runs on".

- The first half (isolated from the other parts) explains reliefs 1 and 2 and promise outcome 1.
- The second half (isolated from the infrastructure) explains relief 3 and promise outcome 3.
- Outcome 2 (runs reliably) rests on reliability by default, named as a mechanism in the promise's support, not as an argument group.

## Evidence

May claim:

- The speed gain from coding agents fades after about two months while code complexity rises 41% and stays up, citing [He et al., MSR 2026](https://arxiv.org/abs/2511.04427). The one linked study.
- A part of the product cannot reach into another; a check fails if it does and says how to fix it (C001; `sandloom explain`).
- One command checks everything and prints `sandloom test: OK` (`run_tests.py:429`, quickstart smoke test).
- A new project comes with rules for the agent (`AGENTS.md`, `CLAUDE.md`, skills) (`project.py:1144`).
- The framework handles saving changes and delivering messages, so a crash or a retry does not leave a change half-saved (C006; positioning row 7).
- One application splits into services by configuration, with the same code (positioning row 9). Fine print one link deeper: moving existing data is a separate step.
- Each part has its own files and tests, so two pieces of work on different parts don't collide (merge test 2026-11-02, people, not agents).

May not:

- Any time ("in 20 minutes"), any speed-up, any number about Sandloom's own effect on agents (not measured; the DX product suite has no stored results).
- That several agents work in parallel successfully (not tried with real agents): say what the structure allows, not what agents achieve.
- That Sandloom stops all decay: it does not stop one part growing tangled inside.
- File counts, byte sizes, the 29 names: measured, but kernel-level detail the page keeps off.
- Named alternatives (FastAPI, Django): positioning keeps them off entry pages.
- "Markdown per page" for agents: in production text, not confirmed in code during this brief; keep `llms.txt` (confirmed in `zensical.toml`) and drop the per-page claim unless checked.

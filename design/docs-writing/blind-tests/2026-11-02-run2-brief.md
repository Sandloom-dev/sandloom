## Pains and reliefs

All five owner-named, in this order (felt result first, then causes, then the rule problem). Each relief uses the pain's nouns.

| # | Pain (plain words) | Relief | Evidence | Strength to respect |
| --- | --- | --- | --- | --- |
| 1 | The first weeks are fast; then every change and every new feature costs more. | The parts stay separate, so the next feature does not have to untangle the last. | [He et al., MSR 2026](https://arxiv.org/abs/2511.04427): velocity up only for the first two months; complexity +41%, static analysis warnings +30%, persisting. `architecture_rules.yml`, CI and pre-commit from `sandloom new`. | Enforced between modules, not inside one; feature cost not measured |
| 2 | The agent can't design an architecture and hold it in mind. | The architecture is already designed: every part has the same layout, and generators create it. | [Dente et al., 2026](https://arxiv.org/abs/2605.06445); `sandloom add` | Where boundaries go is still the reader's call |
| 3 | Tightly coupled code does not split across subagents. | Each part owns its files, tables and tests, so subagents can work on separate parts at once. | [Anthropic C compiler](https://www.anthropic.com/engineering/building-c-compiler), [Cognition](https://cognition.ai/blog/dont-build-multi-agents); two-branch merge test (`agentic-pains.md` pain 3) | Tested with branches, not real parallel agents: "can", not "will" |
| 4 | In a complex project the agent is overloaded and misses connected things. | The agent only has to understand the part it is changing; transactions, logins and data separation are the framework's job. | [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents); generated `AGENTS.md`, `sandloom context` | Context size measured; effect on agents not |
| 5 | Rules in a prompt are only requests: the agent misses or ignores them. | The rules are checks that fail when broken, and the error names the fix. | [Replit incident](https://incidentdatabase.ai/reports/5578/); [Gloaguen et al.](https://arxiv.org/abs/2602.11988); C001/C006 exit 1 | Only rules the checks cover; `src/sandloom/AGENTS.md` lists the rest |

## Evidence

**May claim:**
- He et al.: the two-month gain, +41% complexity, +30% warnings, persisting — the one linked study with its number.
- A cross-module import fails `sandloom check` with SANDLOOM-C001, exit 1 (captured in `README.md`; re-capture before publishing; C001's fix text names stale API, task `check-messages-stale`).
- `sandloom new` writes agent instructions, checks, CI and a pre-commit hook; `sandloom test` ends with `sandloom test: OK`.
- The same module code runs as one app or as separate services, selected by configuration.

**May not claim:**
- Any number or time for "speed of development" (no "in minutes", "10x", "faster by"); METR excluded.
- That feature cost stays flat, or a share of failures prevented — the product suite has not been run.
- "Without rewriting code" stretched to data or deployment: existing data moves in a separate offline step; one link deeper.
- "Never", "cannot", "always" about agents; exactly-once delivery; general security.
- Competitor names (owner's decision).

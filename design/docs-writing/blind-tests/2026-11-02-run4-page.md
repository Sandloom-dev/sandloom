# Sandloom

**Sandloom is a Python backend framework designed for AI-driven development.** You or
your coding agent write the code; the framework gives the agent one starting shape for
every feature, closes each part of the product off from the others, and turns its rules
into checks that name the fix. Your backend stays quick to change as it grows, runs
reliably, and splits from one application into separate services without rewriting code.

## Why coding agents need a framework

A coding agent usually builds a backend on a general web framework, with the rules in a
prompt file. The first weeks are fast; then the architecture decays and every change
costs more. In [a study of projects that adopted an AI coding tool](https://arxiv.org/abs/2511.04427),
code complexity rose 41% and stayed up. The agent cannot design an architecture or hold
the whole system in mind. Several agents in tangled code collide and overwrite each
other's work. Rules in a prompt are requests the agent can ignore. And
moving to separate services means a rewrite.

Sandloom keeps your business logic atomic and isolated from each other and from the
infrastructure: each part of the product is closed off from the others, and the
database, cache or mail service is chosen in configuration. Checks enforce both on every
change. So the architecture stays intact; the agent only needs to understand the part it
changes; several agents can work on separate parts at once; a broken rule fails a
check that names the fix; and the same code runs as one application or as separate
services.

!!! tip "Start here"

    === "With your coding agent"

        ```text
        Set up a Sandloom backend by following https://sandloom.dev/docs/getting-started/.
        Read the AGENTS.md it generates before changing anything. Do not say you are
        done until `uv run sandloom test` prints `sandloom test: OK`.
        ```

        You need Python 3.11+, uv 0.13.4+ and Docker with Compose. You end with a
        backend running on your machine, its checks passing.

    === "Yourself"

        The [quickstart](getting-started/index.md) ends with a backend running on your
        machine, a second part added and its checks passing.

        The [tutorial](getting-started/tutorial.md) then builds a small task list where
        statistics count each new task, and the two parts talk without importing each
        other.

Agents read these docs through [`llms.txt`](llms.txt); every page is also served as
Markdown: add `index.md` to its URL.

## Who it fits

Sandloom fits a backend with several business areas that you and your coding agent keep
changing. Every route requires sign-in unless it is declared public, each customer's data
is kept separate, and sign-in, teams and payments come ready-made.

It is probably not for a tiny endpoint or a short script, an existing application that
cannot be divided into parts, or a team that will not run the checks on every change.

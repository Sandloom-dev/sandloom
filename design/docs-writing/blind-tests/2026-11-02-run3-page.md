# Sandloom

**Sandloom is a Python backend framework designed for AI-driven development.** You can write
the code yourself, but everything is tuned for coding agents: generators, rules the agent
reads, and checks that fail when a rule is broken. Your backend is fast to develop, reliable,
and able to grow from one app into microservices without rewriting code.

## Why coding agents need a framework

With a coding agent, a backend's first weeks go fast; then every change costs more.
In [a study of open-source projects adopting an AI coding agent](https://arxiv.org/abs/2511.04427),
the speed-up lasted two months, while code complexity rose 41% and stayed up. The agent
can't design an architecture and hold it in mind. Tightly coupled code does not split
across subagents. In a large project the agent is overloaded and misses connected things.
And rules in a prompt are only requests: the agent misses or ignores them.

Sandloom keeps each part of your business logic atomic: isolated from the other parts and
from the database and other services it runs on. Checks on every change keep it that way.
The parts stay separate, so the next feature does not untangle the last. The architecture is
already designed: every part has the same layout, and generators create it. Each part owns
its files, tables and tests, so subagents can work on separate parts at once. The agent only
has to understand the part it is changing, while the framework handles transactions,
logins and keeping each customer's data apart. And the rules are checks that fail when
broken, with an error that names the fix.

!!! tip "Start here"

    === "With your coding agent"

        Paste this into your coding agent:

        ```text
        Build a backend with Sandloom, a Python backend framework.
        1. Run: uvx --from "sandloom[standard]==0.7.0a6" sandloom new myapp
        2. Run the next steps it prints, then read myapp/AGENTS.md and follow it.
        3. Add a module for the feature below.
        4. Run `uv run sandloom test` and fix what fails until it prints `sandloom test: OK`.
        Docs: https://sandloom.dev/docs/llms.txt
        Feature: <describe your feature>
        ```

        You need Python 3.11+, [uv](https://docs.astral.sh/uv/) and Docker. The agent is
        done at `sandloom test: OK`, with your feature built and checked.

    === "Yourself"

        The [quickstart](getting-started/index.md) ends with your own backend running on
        your machine.

        The [tutorial](getting-started/tutorial.md) then builds your first feature: a small
        task list where statistics count each new task.

Agents read this site through <a href="llms.txt"><code>llms.txt</code></a>, and every page
is also served as Markdown: append `index.md` to its URL.

## Who it fits

Sandloom fits a backend you build with coding agents and keep growing: several business
areas, customers whose data must stay apart, and features added every week. It works
whether you steer one agent, run several, or review their code.

It is probably not for a tiny endpoint or script. Nor does it fit an existing app whose
internals cannot be split into separate parts, or a team that will not run the checks in CI.

# Sandloom

**Sandloom is a Python backend framework designed for AI-driven development.** You can
write the code yourself, but everything is tuned for coding agents: generators, rules the
agent reads, and checks that fail when a rule is broken. Your backend stays quick to change
as it grows, since those checks keep its parts, one per business area, apart. It runs
reliably: the framework owns transactions, access checks and delivery between parts, so
[a crash does not leave a change half-saved or a message lost](modules/database/units.md).
And it splits from a monolith into microservices
[by configuration](operate/split-into-services.md), without rewriting code.

## Why agents need a framework

Coding agents make the first weeks of a project fast. Then the architecture decays, and
every change and every new feature costs more. In
[a study of GitHub projects that adopted Cursor](https://arxiv.org/abs/2511.04427), the
speed-up lasted two months, while code complexity rose 41% and stayed. An agent cannot
design an architecture and hold it in mind. In a complex project it is overloaded and misses
connected things. Tightly coupled code does not split across subagents. Rules written in a
prompt are requests, and the agent can miss or ignore them.

Sandloom keeps your business logic atomic and isolated from each other and from the
infrastructure. Checks hold the boundaries between business areas however large the backend
gets. An agent only has to understand the part it is changing, and that part is small enough
to hold in mind. Each part owns its files and tests, so several agents work side by side.
A broken rule fails a check instead of waiting in a prompt.

!!! tip "Start here"

    === "With your coding agent"

        Paste this prompt into your coding agent:

        ```text
        Build a backend for <what your product does> with Sandloom, a Python backend framework.
        Read https://sandloom.dev/docs/llms.txt, then follow the quickstart at
        https://sandloom.dev/docs/getting-started/ to create the application.
        Read the AGENTS.md that `sandloom new` writes and follow its rules.
        Before you say a change is done, run `uv run sandloom test` and show me
        that it ends with `sandloom test: OK`.
        ```

        You need Python 3.11+, [uv 0.13.4+](https://docs.astral.sh/uv/) and Docker with
        Compose. The last step, `uv run sandloom test`, runs the tests and every check.

    === "Yourself"

        1. **[Quickstart](getting-started/index.md)**: go from an empty folder to a backend
           running on your machine, with its tests and checks passing.
        2. **[Tutorial: your first feature](getting-started/tutorial.md)**: build a small
           task list whose two parts talk to each other: a statistics part counts each new task.

Agents read these docs through [`llms.txt`](llms.txt), an index of every page, and each
page is also served as Markdown.

## Who Sandloom fits

Sandloom builds on FastAPI and SQLAlchemy and runs on PostgreSQL and Redis. It fits a
backend with several business areas that people and coding agents keep changing. A product
that needs sign-in, access control and each customer's data kept separate gets them
ready-made. A backend that starts as one application can later split into services and keep
its code.

It is probably not for a tiny endpoint or a short script, where the structure costs more
than it saves. An existing application whose internals cannot be cut into isolated parts
fits poorly too, and so does a team that does not want to follow the rules and run the
checks in CI.

# Sandloom

**Sandloom is a Python backend framework designed for AI-driven development.** You or
your coding agent write the code; generators give it a starting point, project rules tell
it how to work, and checks that fail stop it when it breaks a rule. Your backend stays
quick to change as it grows, runs reliably, and splits from one application into services
without a rewrite. <!-- prose-ok: S8 the outcome is backed by the mechanism in the sentence before -->

## Why AI-driven code needs boundaries that hold

With a coding agent writing the backend, the first weeks are fast, then every change
costs more. In projects that adopted an AI coding tool,
[code complexity rose 41% and stayed up](https://arxiv.org/abs/2511.04427), and that
complexity drove the later slowdown. An agent can't design an architecture and hold it in
mind. Several agents can't work at once on tangled code. In a complex project the
agent is overloaded and misses connected things. Rules in a prompt are only
requests. Moving from one application to services usually means a rewrite.

Sandloom keeps each part of your product's business logic closed off from the other parts
and from the database, cache and mail service it runs on. Checks hold those boundaries: a
broken rule fails a check that names the fix, so rules stop being requests. Because each
part is closed off, changes stay quick as the backend grows and several agents can work at once. <!-- prose-ok: S8 backed by the closed-off parts and the checks in the same paragraph -->
Generators and skills set the shape, so the agent only has to understand the part it
changes, not crash safety or login checks. The same code splits into services by
configuration.

!!! tip "Start here"

    === "With your coding agent"

        Paste this prompt:

        ```text
        Create a new backend with Sandloom (https://sandloom.dev/docs/llms.txt): run
        `uvx --from "sandloom[standard]==0.7.0a6" sandloom new myapp`, follow the printed
        steps, add a part of the product for <what you build>, and finish only when
        `uv run sandloom test` prints `sandloom test: OK`.
        ```

        You need Python 3.11+, uv and Docker. The agent hands you the part you described,
        running on your machine with its checks passing.

    === "Yourself"

        Follow the [quickstart](getting-started/index.md) to create a backend
        running on your machine with sign-in, teams and payments.

        Then work through the [tutorial](getting-started/tutorial.md) to build a small task
        list where statistics count each new task.

Your agent reads these docs through <a href="llms.txt"><code>llms.txt</code></a>, and you can
get every page as Markdown by appending `index.md` to its URL.

## Who Sandloom fits

Sandloom fits a backend with several business areas that you and your agents keep
changing. Checking logins and keeping each customer's data separate are built in, not
left to the agent. A crash or a retry can't half-save a change or charge twice.

It is probably not for a tiny endpoint or a short script, where the structure costs more
than it saves. Nor does it suit an existing application that can't be divided into
parts, or a team that won't run the checks before every merge.

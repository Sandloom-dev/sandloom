# Sandloom

**Sandloom is a Python backend framework designed for AI-driven development.** You or your
coding agent write the code; generators give the code a starting point, project rules tell
the agent how to work, and checks that fail stop the agent when it breaks a rule. Your <!-- prose-ok: S8 the outcome is backed by the mechanisms in the sentence before -->
backend stays quick to change as it grows, runs reliably, and splits from one application
into services without a rewrite.

## Why backends built with agents slow down

When an agent writes most of a backend, the first weeks are fast, then every change
costs more. In a [study of projects that adopted Cursor](https://arxiv.org/abs/2511.04427),
code complexity rose 41%, stayed up and drove that slowdown. Given no architecture, the
agent invents one task by task, and the code tangles. Tangled code can't be split between
several agents, and in a large project the agent misses what its change is connected to.
Rules in a prompt are only requests, so on a long task the agent drops the one that
mattered. Moving one application to services usually means a rewrite.

Sandloom keeps the business logic of each part of your product closed off from the others
and from the database, cache and mail service. A check fails when code breaks a rule, and
names the fix. Because the parts stay closed off, changes stay quick as the backend grows, <!-- prose-ok: S8 backed by the closed-off parts and the checks in the same paragraph -->
and several agents can work on them at once. Generators and project rules give
each feature its shape, so the agent reads a page about the part it changes. Saving is Sandloom's job: a crash
or retry does not half-save a change or charge twice. Since business code depends on neither
the other parts nor the database, one application
[splits into services](operate/split-into-services.md) by configuration, with the same code.

!!! tip "Start here"

    === "With your coding agent"

        Paste into your agent:

        ```text
        Create a new backend with Sandloom (https://sandloom.dev/docs/llms.txt): run
        `uvx --from "sandloom[standard]==0.7.0a6" sandloom new myapp`, follow the printed
        steps, add a part of the product for <what you build>, and finish only when
        `uv run sandloom test` prints `sandloom test: OK`.
        ```

        You need Python 3.11+, [uv](https://docs.astral.sh/uv/) and Docker. You end with a
        running backend whose first feature passes `uv run sandloom test`.

    === "Yourself"

        Start with the [quickstart](getting-started/index.md): you end with a backend running
        on your machine, with sign-in, teams and payments.

        Then the [tutorial](getting-started/tutorial.md) builds a small task list whose
        statistics part counts each new task.

Agents read these docs through [`llms.txt`](llms.txt), and every page is served as
Markdown: append `index.md` to its URL.

## Who Sandloom fits

Sandloom fits a backend of several business areas, changed by you and your agents, that
keeps each customer's data separate and may later split into services. Login
checks and that separation are built in, not left to the agent.

It is probably not for a tiny endpoint or script, an existing application that can't be
divided, or a team that won't run the checks in CI.

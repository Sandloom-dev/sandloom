# Sandloom

**Sandloom is a Python backend framework designed for AI-driven development.** You can write the code by hand, but the framework is built for coding agents: generators give them a starting point, project rules tell them how to work, and automated checks stop them when they break a rule. Your backend stays quick to change as it grows, runs reliably, and can scale from a single application to microservices without a rewrite.

## Why agents need a framework

Coding agents write features quickly, but that speed fades as a backend grows. In [a study of GitHub projects adopting Cursor](https://arxiv.org/abs/2511.04427), the gain lasted two months, while code complexity rose 41% and stayed there. The agent has to design the structure, remember it and obey rules nothing enforces, so in a big project it misses what depends on what. Each change reaches into other parts, so every feature costs more than the last and agents working in parallel collide. Calls between parts assume one process and one database, so moving to services means a rewrite while the product grows fastest.

Sandloom keeps each part of your product closed off from the others and from the database, cache and mail service it runs on. Generators and project rules give every feature the same shape. Checks fail when code breaks a rule, so the structure no longer lives in the agent's memory. Parts talk only through declared calls and messages, so a change stays inside its part and two parts can change on separate branches. The same code splits into services through configuration; existing data moves [as its own step](operate/split-into-services.md).

!!! tip "Start here"

    === "With your coding agent"

        Your agent needs Python 3.11+, uv and Docker.

        ```text
        Build this backend with Sandloom: <what my product does>

        Follow https://sandloom.dev/docs/getting-started/index.md to create the project,
        then follow the AGENTS.md it generates.
        Finish only when `uv run sandloom test` prints `sandloom test: OK`.
        ```

    === "Yourself"

        New to Sandloom? The **[quickstart](getting-started/index.md)** takes you from an empty folder to a backend running on your machine, with sign-in, teams and payments.

        Then follow **[Tutorial: your first feature](getting-started/tutorial.md)**. Step by step, you build a small task list where a statistics part counts each task you add.

Agents can read these docs directly: <a href="llms.txt"><code>llms.txt</code></a> is the index, and every page is also served as Markdown when you append `index.md` to its URL.

## Who Sandloom fits

Sandloom fits a backend with several business areas that people and coding agents keep changing. Login checks and keeping each customer's data separate are built in, not left to the agent, and a crash or a retry does not half-save a change or charge twice.

It is probably not for a tiny endpoint or a short script, where the structure is more work than it saves. The same goes for an existing application that can't be divided into parts, or a team that won't run the checks in CI.

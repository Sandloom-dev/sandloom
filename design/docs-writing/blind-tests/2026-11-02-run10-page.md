# Sandloom

**Sandloom is a Python backend framework designed for AI-driven development.** You or your
coding agent write the code. Sandloom keeps each part of your product closed off, checks the
project's rules on every change, and gives the agent skills and tools to start from. Your backend
stays quick to change as it grows, runs reliably, and splits from one application into services <!-- prose-ok: S8 outcome backed by the mechanisms in the same paragraph -->
without a rewrite.

## Why AI-driven backends tangle as they grow

With a coding agent, early speed fades. In
[GitHub projects that adopted Cursor](https://arxiv.org/abs/2511.04427), development sped up
only in the first two months, but code complexity rose 41% and stayed there. The agent must
design the structure, remember it and obey rules nothing enforces, so in a big project it misses
what depends on what. Each change reaches into other parts, so every
feature costs more than the last and two agents collide. Calls between parts assume one process
and one database, so splitting into services means a rewrite while the product grows fastest.

Sandloom answers by keeping each part of your product
[closed off](architecture.md#design-principles) from the others and from the servers it runs on.
Generators give the agent a starting point, project rules describe the structure, and checks
fail when it breaks one, so nothing rests on its memory. Parts talk only through
declared calls and messages, so a change stays inside its part and two parts can change on
separate branches. You [split into services](operate/split-into-services.md), or point at
another database, cache or mail service, in configuration, not code; existing data moves
[as its own step](operate/split-into-services.md#existing-data).

## Start here

!!! tip "Choose who writes the code"

    === "With your coding agent"

        You need Python 3.11+, uv 0.13.4+ and Docker. Paste this prompt into your agent:

        ```text
        Build a Python backend with Sandloom. Read
        https://sandloom.dev/docs/getting-started/index.md and follow it to create
        the application. Then read the AGENTS.md file it generates and follow it for
        every change. Before you say you are done, run `uv run sandloom test` and fix
        what it reports until it passes.
        ```

        You end with a backend running on your machine, with every check passing.

    === "Yourself"

        Follow the [quickstart](getting-started/index.md). You end with a backend running on
        your machine, with sign-in, teams and payments.

        Then, in the [tutorial](getting-started/tutorial.md), you build a small task list where
        a statistics part counts each task you add.

Agents read these docs through <a href="llms.txt"><code>llms.txt</code></a>; every page is
served as Markdown: append `index.md` to its URL.

## Who it fits

Sandloom fits a backend with several business areas that you and your agent keep changing. It suits a product that must keep [each customer's data separate](modules/guarantees/index.md),
check who is logged in and pass messages reliably between parts, and that may run as services later.

It is probably not for a tiny endpoint or a short script, where dividing the code costs more
than it saves. Nor does it suit an application that can't be divided into parts, or a team that
won't run the checks in CI.

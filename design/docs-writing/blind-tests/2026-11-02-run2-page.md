# Sandloom

**Sandloom is a Python backend framework designed for AI-driven development.** You can write
the code yourself, but everything is tuned for coding agents: generators, rules the agent
reads, and checks that fail when a rule is broken. Your backend is fast to develop, reliable,
and able to grow from one app into microservices without rewriting code.

## Why coding agents need a framework

With a coding agent, the first weeks of a backend go fast. Then every change and every new
feature costs more. In [a study of projects that adopted an AI coding tool](https://arxiv.org/abs/2511.04427),
the speed-up lasted two months, while code complexity rose 41% and stayed up. The agent can't
design an architecture and hold it in mind. Tightly coupled code does not split across
subagents. In a complex project the agent is overloaded and misses connected things. Rules in
a prompt are only requests: the agent misses or ignores them.

Sandloom keeps each part of your business logic atomic: isolated from the other parts and from
the infrastructure it runs on. The parts, called modules, stay separate, so the next feature
does not have to untangle the last. The architecture is already designed: every part has the
same layout, and generators create it. Each part owns its files, tables and tests, so
subagents can work on separate parts at once. The agent only has to understand the part it is
changing; transactions, logins and keeping each customer's data separate are the framework's
job. The rules are checks that fail when broken, and [the error names the fix](reference/error-codes.md).

!!! tip "Start here"

    === "With your coding agent"

        You need Python 3.11+, [uv](https://docs.astral.sh/uv/) and Docker. Paste this prompt
        into your agent: <!-- sandloom-release -->

        ```text
        Build a backend with Sandloom.
        1. Run: uvx --from "sandloom[standard]==0.7.0a6" sandloom new myapp
        2. Run the steps it prints (they start the local database), then follow myapp/AGENTS.md.
        3. Build this feature in its own module (uv run sandloom add module <name>): <your feature>
        4. Run: uv run sandloom test
           You are done only when it prints "sandloom test: OK".
        ```

        You end with a running backend, your feature and passing checks.

## Who Sandloom fits

Sandloom fits a product backend that coding agents keep changing as it grows, whether you
steer one agent, run several, or review what they write. It pays off with several business
areas and customer data to keep apart.

It is probably not for a tiny endpoint or script, where the structure costs more than it
saves. Nor does it fit an existing app whose code cannot be cut into separate parts, or a team
that will not run the checks on every change.

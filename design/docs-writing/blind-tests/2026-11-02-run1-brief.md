## Job

## One message

Proposal: **"Sandloom is a Python backend framework designed for agentic development: it turns the architecture rules your agent tends to break into defaults and checks, so the project stays fast to change as it grows."**

Shorter form for the bold first sentence: **"A Python backend framework designed for agentic development."** (README, website and production page all use "for AI-driven development"; the request says "designed specifically for agentic development". See Open 2.)

## Promise

What the reader's backend gets, as outcomes they would pay for (three, per entry voice):

1. **It stays quick to change as it grows.** The tenth feature costs about what the second did, because each feature lives in its own part of the product and the checks keep the parts apart. (Unmeasured; say it as the mechanism, not as a number. See Evidence.)
2. **It runs reliably.** Login checks on every route, each customer's data kept separate, and no lost or doubled writes on a retry: the framework does these by default, so the agent cannot forget them.
3. **It can grow into services.** Start as one application and move parts into separate services by configuration, without rewriting them.

Plus, for the person steering: **you can tell when the agent is done.** One command runs every check and names the fix for each failure.

## Pains and reliefs

Order: the felt result first, then its causes, then how it shows (the pains file's own order). An entry page has room for about five; the full twelve live in `agentic-pains.md`. Proposed five, each relief in the same nouns as its pain:

| # | Pain (way of working, no Sandloom term) | Relief | Evidence | Pains-file row |
| --- | --- | --- | --- | --- |
| 1 | The first weeks are fast; then every change costs more, because the code tangles. | The boundaries are checked on every change, not only at the start, so the project keeps its shape as it grows. | [He et al., MSR 2026](https://arxiv.org/abs/2511.04427): velocity rises only in the first two months after adopting Cursor; static-analysis warnings +30%, complexity +41%, and the complexity drives the slowdown. Mechanism: `sandloom new` writes `architecture_rules.yml`, a CI job running `sandloom test --ci` and a pre-commit `sandloom check`. | 1 |
| 2 | In a large project the agent cannot hold the whole system in mind and breaks a place it never read. | The agent only has to understand the part it is changing: parts of the product cannot reach into each other, and a change that breaks another part's interface fails a check. | [Anthropic, context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents): recall falls as context grows. [DORA 2025](https://cloud.google.com/blog/products/ai-machine-learning/announcing-the-2025-dora-report). Mechanism: C001, snapshots T004/T005/T007; `sandloom context <module>` gives a 1.1 KB map. | 4, 6 |
| 3 | Rules in a prompt are requests: the agent misses or ignores them. | The rules that matter are code: defaults the agent gets without asking, and checks that fail with the fix. | [Gloaguen et al.](https://arxiv.org/abs/2602.11988): context files do not generally raise success. Captured: `sandloom check` exits 1 on C001 and C006 (below). | 5 |
| 4 | What nobody asked for does not get written: login checks, separate customer data, safe retries. | The framework does them by default: a route requires login unless it says why not, customer rows are filtered, and the framework owns the transaction and event delivery. | [Veracode 2025](https://www.veracode.com/press-release/ai-generated-code-poses-major-security-risks-in-nearly-half-of-all-development-tasks-veracode-research-reveals/) (vendor): vulnerabilities in 45% of tasks. Mechanism: B008, `TenantScoped` + RLS, units and outbox. | 8, 9 |
| 5 | It looks done and it is not. | One command runs every check, so "done" means the checks passed. | [Stack Overflow 2025](https://survey.stackoverflow.co/2025/ai): 66% name "almost right" as the top frustration. Mechanism: `sandloom test`, error codes with `sandloom explain`. | 10 |

## Evidence

**May be claimed**, with its source:

- The He et al., Anthropic, DORA, Gloaguen, Stack Overflow findings as summarised in `agentic-pains.md`, linked.
- Captured in this copy on 2026-11-02, `sandloom check` on a generated app with a sibling import:
  ```text
  sandloom check: 1 architecture violation(s)

    myapp/modules/reports/bad_import.py:1: error[SANDLOOM-C001 module-boundaries]: from myapp.modules.notes.services import ...
  ```
  exit code 1. And with `await db().commit()` in module code: `error[SANDLOOM-C006 uow-boundary]: .commit()`, exit code 1.
- `sandloom new myapp --no-batteries --module notes` writes 44 files, among them a 53-line, 2,889-byte `AGENTS.md` and a `CLAUDE.md`.
- Ordinary modules need 29 SDK names (`AGENTS.md`, glossary).
- A route is authenticated unless it declares `public(reason=)`; the framework commits; events are delivered at least once and a durable consumer handles each once.
- Same module code in one process or several, chosen by configuration.

**May not be claimed:**

- Any speed-up, time saved, or cost of the Nth module: nothing measured (the DX eval product suite `p3_add_module_n2` / `p4_add_module_n7` has no stored result).
- METR figures; the 167k–257k-token baseline (predates the current tooling).
- That Sandloom stops decay inside one module, wrong business logic, or general security holes; that it sandboxes an agent (the Replit incident must not read as a promise).
- That parallel agents work without conflict (tested with two branches, not agents).
- "Moves data to its own database by configuration": moving existing data is a separate offline step.

**Do not show as proof as captured:** the C001 "How to fix" text names stale API ("publish_event / register_event_consumer … core.get_service"), confirmed in the capture. Show only the error line, or fix the message first (task `check-messages-stale`).

## Tone

From the request and the entry voice: confident first (what Sandloom is and gives), then the pains as pains of the way of working, never as Sandloom's own. Mirror the pains in the reliefs. Threes in parallel grammar. Outcomes over adjectives. Plain words. Prose for the argument, cards only for choices. Honest fit. Only measured numbers. Must make the reader want to try it: the action sits in the first screen after the pains.

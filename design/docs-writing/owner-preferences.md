# The owner's preferences

Corrections the owner made to docs drafts, each kept as the rule it implies so no page needs it twice. Writers read this before drafting ([sandloom-docs-writing](../../.claude/skills/sandloom-docs-writing/SKILL.md)); reviewers check against it ([sandloom-docs-review](../../.claude/skills/sandloom-docs-review/SKILL.md)), and add a line after each correction that applies beyond its page. Quotes are translated from the owner's Russian.

| Date, page | The owner said | The rule |
| --- | --- | --- |
| 2026-11-02, Overview | Architecture belongs on its own page | An entry page carries no architecture; it links to How Sandloom works |
| 2026-11-02, Overview | "We say how great we are, and right after it problems, as if we had problems" | Pains follow the promise as pains of the way of working, never as the product's own |
| 2026-11-02, Overview | "I don't like the bullets either" | Arguments are prose; lists hold only choices |
| 2026-11-02, Overview | "The idea is right, but the language and the form of the sentences are rickety" | An accepted idea still gets a language pass before it is shown |
| 2026-11-02, Overview | An outside developer stumbled on "modules": "immerse gradually" | A page uses only the terms its level allows ([audience.md](../../.claude/skills/sandloom-docs-writing/audience.md)) |
| 2026-11-02, Overview | "I didn't ask to change it, put it back" | Change only the block under discussion; propose anything else |
| 2026-11-02, Overview | "First just move it as is" | Reused blocks move unchanged first, then get edited in their own step |
| 2026-11-02, Overview | "Strange that a framework for agents has nothing on its main page to give an agent" | Every entry page has a path for an agent: a prompt to paste |
| 2026-11-02, Overview | "Change of voice" | One voice, "you", across the whole page |
| 2026-11-02, Overview | "Start with you / Start with your coding agent looks like nobody thought about it"; "By hand" rejected | Labels and tab names are drafted with alternatives and chosen, not left at the first try |
| 2026-11-02, Overview | "Both say first feature, and two parts of something" | Two links never promise the same result, and each names a concrete one |
| 2026-11-02, Overview | "20 minutes isn't needed there" | No time or number nobody measured |
| 2026-11-02, Overview | Cards "like on the site" | Reuse the site's components before inventing a layout |
| 2026-11-02, positioning | Entry pages do not name alternatives | Speak about the pains, not competitors |
| 2026-11-02, positioning | "AI-driven development" | The term across the whole site, never "agentic development" |
| 2026-11-02, skills | "There can be many advantages and problems; the agent should pick a reasonable number of the strongest that can be logically combined" | A page argues from the strongest few pains and advantages, grouped by a shared cause; the rest go deeper |
| 2026-11-02, Overview | "Yes, the limit can be raised" | An entry page has up to 550 words of prose; the strongest versions did not fit in 450 |
| 2026-11-02, Overview | "Too many technical details" on the built-in edge cases | An entry page explains how, but simply: no deep technical detail, in words a complete outsider understands |
| 2026-11-02, Overview (run 13) | "Keep my page. The agents wrote well, but my language is better, and they write about a shop: that may confuse visitors who build something else" | An entry page carries no running example from one business domain; it speaks of the reader's own backend. The owner's page stays; agents' versions are proposals for single sentences, not replacements |
